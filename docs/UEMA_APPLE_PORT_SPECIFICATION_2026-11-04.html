UEMA on Apple platforms: specification, November 4, 2026

Verdict. Target A, the macOS Python port, is a set of device-agnostic changes to the released trainer, each verified here on the CPU device. Target B, the Swift package UEMAKit and the SwiftUI app UEMA Mind, is a new inference-only program: one MIMo body in MuJoCo, the released forward model and planner, written here, compiled only when the founder opens it on a Mac. Learning on the device is out of scope (section 6).

The setting. MIMo is a simulated infant body described in MuJoCo XML (the text format of the physics program): 75 <geom> elements (collision and drawing shapes), 97 joints and 92 <motor> elements in MIMo_metav2.xml and MIMo_modelv2.xml [I2 mimo-body]; the crib scene compiled from the committed bundle holds 188 geoms, 146 joint-position numbers (nq), 90 actuators (nu) and 6 cameras (apple/UEMAKit/Sources/UEMAScene/Resources/crib_age24_trunk_v1/bundle.json, model_counts). MuJoCo 3.3.0, the physics program, moves the body; UEMA, the learning program, controls it. Every model step (one 50 ms model update: 5 env steps of 10 ms, each 2 physics steps of 5 ms [I2 env.py:1157]) UEMA reads six senses, encodes each into one token (a vector of 192 numbers), predicts the next tokens with the forward model (a transformer: a stack of 4 attention blocks, each mixing all tokens of the last 128 model steps) and sends the motors a command (26 body handles x 9 numbers: target position x y z in cm, orientation as a quaternion x y z w, radius, strength 0 to 1 [I1 README.md:19; I2 movement_viewer/__init__.py]). Every 10 model steps the planner changes the command by gradient descent (repeated small changes, each against the gradient of a score) through the frozen forward model toward a goal taken from the goal ring (the tokens of the last 200 model steps, deque(maxlen=200) at lem_model.py:998 on this branch) and ranked by wellness (the sum of the wellness channels). The released trainer runs on Windows 11 with an NVIDIA graphics card [I1 README.md:123]; the released checkpoint is model step 494,025 of run B1K_skip13_492800 [I1 resume.py].

Who does what. The founder owns the Mac, the iPhone and every decision; the author writes this page and the code; a reviewer who did not write them reads both.

What is being specified, and what is not?

Purpose. Requirements a test can pass or fail for: (A) the released Python trainer on macOS with the device chosen at launch (cuda: an NVIDIA graphics card; mps: torch's name for the Apple graphics processor through Metal, Apple's graphics programming interface; cpu); (B) UEMAKit, a Swift package (a library built by Apple's Swift compiler), plus UEMA Mind, a SwiftUI app (SwiftUI: Apple's user-interface framework) for iOS 17 and macOS 14 or later, which steps the MIMo body in MuJoCo, computes the six senses, runs the released forward model and planner and sends commands: no learning, one world. UEMA Mind's Xcode project is apple/UEMAMind/ with the schemes UEMAMind-macOS and UEMAMind-iOS (apple/README.md); the page calls the app UEMA Mind. Non-goals: section 6.

Fixed facts that bound this specification and the implementation plan.
  1. Build machine: Windows 11, no Swift toolchain, no Xcode (Apple's development program); Swift code written now compiles only when the founder opens it on a Mac, so every Swift work item ends with the first-build checklist (REQ-B-18) and only the Python work items are verified by running.
  2. The Python port is verified here on the CPU device (torch "cpu") standing in for the Metal device (torch "mps"): one world, never eight, and only when mimo_bridge/tools/free_memory_guard.py --need-gb 12 exits 0 (free physical memory at or above 12 GB, 1 GB = 1,073,741,824 bytes). No measurement in the evidence files sets the 12 GB line; REQ-A-12's measured one-world peak resident memory replaces it.
  3. Every file is committed to the Git branch feature/apple-port-2026-11-04: new files under apple/ (Swift package and app), device-agnostic changes under Source/Python, and every machine-written record under apple/records/.
  4. The user interface is SwiftUI only.
  5. SOLID (five design rules: single responsibility, open for extension and closed for change, Liskov substitution, interface segregation, dependency inversion): one responsibility per type; protocols (Swift interfaces) for physics, senses, encoders, forward model, planner, weights loading, rendering; concrete types built only at the composition root and injected, never constructed inside their users (section 5).
  6. The released model: 18,131,745 parameters, d_model (token width) 192, 4 transformer blocks, context 128 model steps, six active senses, one 192-number token per sense per model step [I1 trainer.log, receipt]. The senses: vision (5 rendered camera images), tactile (contact forces on 4,683 skin points), audio (a 256-bin spectrum per ear), proprioception (the pose and motion of 26 body rows), motor (the achieved and commanded state of the 26 body handles) and vestibular (head acceleration and rotation); intermind (a sense for another mind's signals) is not active. The released run's scene is "crib" and the body is primitive geoms with no mesh files [I2 args.json, MIMo_modelv2.xml].
  7. Apple-side facts come only from research1.json [R1]; every Apple-side fact this page uses from elsewhere is marked "unverified" where it is used.

What is the system today, and where does each part run?

  • resume.py (Windows, Python 3.13.3) reads the saved command (weights/b1_continue_B1K_skip13_492800/run/command.json, 353 arguments), replaces its output and resume paths and starts train_mimo.py as a child process. train_mimo.py, the child of resume.py and the parent of the eight world processes, runs the model-step loop on cuda:0; its flag --eval-only is "act but do not learn (weights frozen)" [I1 resume.py:49, :89; train_mimo.py:315].
  • PoolSource starts 8 world processes with the "spawn" start method (a fresh Python interpreter per process), one Pipe (a two-way byte channel) each [I1 datasource.py:495]. SingleEnvSource runs one world inside the trainer's process without a pipe [I1 datasource.py:295-296].
  • BridgeEnv (env.py, 3,714 lines), one per world process: one MIMo body in the crib (a mobile, toy critters and a responsive caregiver, age 24, trunk_v1 body layout); 5 env steps per model step; EyeRenderer draws 5 cameras with MuJoCo's classic OpenGL renderer (OpenGL: a cross-platform graphics programming interface) on one mujoco.GLContext per process [I2 env.py:47, :599-638; args.json].
  • The bridge files (5,702 lines in numpy, Python's array library; env.py's 3,714 lines are among them): touch_adapter (TouchPooler, 388 lines), proprio_adapter, vestibular_adapter, vision_adapter, action_decoder (527 lines), touch_inside_rays and contact_mechanics produce every number the model receives. Of the MIMo package (12,329 lines), TrimeshTouch (the skin-contact model) and SpringDamperModel (the actuator model) run inside each step; the bridge reads proprioception and vestibular arrays itself, so SimpleProprioception and SimpleVestibular are not the producers of the model's inputs, and SimpleVision is unused [I2 mimo-body, tokenizer].
  • LemLite (lem_model.py), in train_mimo.py's process: bf16 autocast on cuda (bf16: a 16-bit number format with 8 bits of precision; autocast: torch's switch that runs chosen operations in that format) and float32 without autocast elsewhere; 6 encoders; forward model (4 blocks, 8 attention heads, width 192, 768 tokens = 6 senses x 128 model steps); prediction heads; motor controller; wellness; planner; 18,131,745 parameters [I1 receipt; lem_model.py:785-800].
  • Checkpoint ckpt_step_494025: model.safetensors 73,119,988 bytes (safetensors: a file of named arrays; 18,131,745 float32 parameters fill 72,526,980 bytes, and the other 593,008 bytes are the 91,104-byte header and 126 buffer tensors of 168,674 elements, apple/UEMAKit/Sources/UEMAModel/Resources/weight_manifest.json counts); optimizer.pt 138,060,045 bytes; runtime_state.pt 489,337,136 bytes; episode_state.pt.gz 621,243,950 bytes [I1 MANIFEST.json].

Measured cost today [I1 README.md:125; stats record]: 0.41 to 0.46 model steps per second with 8 bodies on the RTX 4070 laptop; per model step, model 1,984.3 ms and worlds 250.4 ms (learning included); graphics memory peak 4,287 MB; committed memory rose from 44.0 to 73.8 GB. Inference-only cost is not measured in any release file.

One responsibility per type; every user of a part depends on a protocol; concrete types are built only at the composition root and injected.
