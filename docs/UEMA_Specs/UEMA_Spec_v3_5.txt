Part I: Foundations
1. Core Thesis: Why Policy Networks Cannot Achieve Genuine Mind
Policy networks learn a mapping: observation → action. This collapses five distinct cognitive stages into one undifferentiated mapping:
I perceive  →  I predict  →  I feel myself  →  I intend  →  I act
Five distinct stages. Each must be a meaningful internal process with its own computational substrate. A policy network collapses all five into f(observation) = action.
The Zombie Problem: A policy network has no internal state representing WHY an action works. It is purely reactive. There is nothing it is LIKE to be this system.
No Permanent Policy Exceptions: This thesis applies to the ENTIRE system. There is no permanent RL reflex layer. There is no bootstrap scaffold. The grounded wellness evaluator provides gradient signal from frame zero over PCC-stabilized baseline posture. Developmental constraints (Section 9.4) limit the search space to all handles at very low strength (2%) and minimal ROM (5%) initially. Every motor command flows through the prediction-wellness architecture from the start.
2. The Dual Objective: Prediction Error and Wellness
Prediction Error (PE) drives world-model learning. The forward model minimizes PE about sensorimotor experience. PE is how the system comes to UNDERSTAND the world. Prediction is compression; to predict well you must understand the underlying process.
Wellness gradient drives action selection. The wellness evaluator maps current sensory state to a multi-dimensional wellness vector. Its gradient with respect to motor parameters determines WHICH actions are generated.
Why both are necessary: PE alone: system could minimize PE by sitting still (no motivation). Wellness alone: system might learn shortcuts without deep world models. Together: PE builds accurate world model, wellness drives self-preserving action on that model.
Everything else emerges from this dual objective:
Emergent Phenomenon	Mechanism
Curiosity	Seek states where PE is moderate—high learning potential
Boredom	PE → 0 in current domain—seek novelty
Self-coherence	Maintain predictive accuracy about 'self'—most complex prediction set
Self-preservation	Protect body model—most valuable predictive asset
Intention	Invert forward model—desired consequence → action
Imagination	Chain forward model without executing—simulate before committing energy
Stress	Sustained multi-modal PE without resolution
Grief	Deeply reinforced prediction becomes permanently false
No external curriculum. No task-specific reward. No permanent RL reward signal anywhere.

Part II: The Perception-Prediction Duality
4. The Two Registers of Experience
4.1 The Grounded Register
Perception IS sensor data. The Grounded Perception State P_t is the complete, uncompressed state of all sensors at time t. Every dimension corresponds to a measurable physical quantity.
P_t = {
  vision:        {fovea_tokens[1024,768], pano_tokens[15229,768], angular_pos[16253,2], gaze_target},
  tactile:       {patches: List[{normalPressure, shearMagnitude, slipRate, contactArea, vibPower[4]}]},
  audio:         {left_spectrum[256], right_spectrum[256], itd, ild, self_voice_coherence},
  proprioception:{joint_pos[n_joints,3], joint_vel[n_joints,3], ph_forces[n_handles,3],
                  ph_targets[n_handles,7], pcc_strengths[n_bodysets], muscle_cap[n_bodysets], energy},
  motor_commands:{ph_commands[n_handles,9]}
}
4.2 The Predictive Register
Plain-English Intuition: What Encoding Does | The problem: Raw sensor data is enormous. Vision alone is 16,253 patches times 768 numbers each. Tactile is 200 patches times 8 numbers. Audio, proprioception, motor commands—all together this is millions of numbers per frame. No neural network can efficiently predict “what happens next” from millions of raw numbers. | The solution: Compression. Each sense gets squeezed down to 768 numbers (a “token”). Vision’s 16,253 patches become one token of 768 numbers. Tactile’s 200 patches become one token of 768 numbers. Six senses, six tokens, each 768 numbers. That is the entire state of the system compressed into 4,608 numbers. | What is lost: Detail. You cannot reconstruct the original 16,253 vision patches from 768 numbers. Information is thrown away. This is lossy compression, like JPEG for images. The encoder learns WHICH information to keep: the information most useful for predicting what happens next. | “Learned jointly with forward model”: The encoder’s compression is trained together with the prediction system. If the encoder throws away information that the predictor needs, prediction gets worse, gradients flow back, and the encoder learns to keep that information. The encoder learns what matters by being punished for throwing away useful things. | “Only runs on real data”: The encoder only compresses actual sensor data. During imagination (chained prediction), the system works with already-compressed tokens. It does not re-encode imagined states because there is nothing to encode—there are no real sensors firing during imagination. | Analogy: Think of it like summarizing a book into a one-paragraph summary (encoding). You can reason about the summary (prediction in token space). You can even imagine what the next chapter’s summary might be (chaining). But your imagined summary is not as rich as actually reading the next chapter (grounded register). And you cannot reconstruct the full book from just the summary (lossy).
Encoding compresses P_t into d_model tokens for imagination rollout. Six modality tokens:
z_t = {z_vision, z_audio, z_tactile, z_proprio, z_motor, z_intermind}  // each Tensor[768]
Properties: lossy (cannot reconstruct P_t), learned (jointly with forward model), only runs on real data (imagination chains z without re-encoding).

4.3 Reconciliation
Situation	Register	Wellness Evaluator	Motor Source
Execution	Grounded (P_t)	Grounded (authoritative)	Adaptive motor controller
Imagination	Predictive (z_t)	Approximate (trained to match)	Intention generator
Retrospection	Both (compare)	Both (training signal)	None (learning only)
Imagining pain does not hurt: this is the phenomenological gap between registers. The system learns to model this gap. The Grounded Register is authoritative (all evaluation happens here). The Predictive Register is approximate (all prediction and planning happens here). The gap between registers IS self-knowledge: the system learns that its imagination of pain differs from actual pain by a measurable amount. This discrepancy is the computational basis for distinguishing reality from thought.
Part III: Modality Encoders
Each modality has a specialized encoder compressing raw data into d_model=768 tokens. All encoders process at d_model width internally (768-dim attention, 768-dim MLPs) and are trained jointly with the forward model. There is no intermediate bottleneck dimension; the encoder learns what information to discard at the final pooling step, not before.
5. Encoder Specifications
5.1 Vision Encoder
Architecture: patch_embed(Linear 768→768) + AngularPositionEncoding + SwinTransformer(4 layers) + AttentionPooling. Input: 16,253 raw patches. Output: pooled vision token [768] + full patch sequence for downstream attention. Rate: 24 Hz (human visual cortex V4/IT operates at 20–30 Hz; see Section 24.4). The forward model reuses the latest z_vision between vision updates. All other encoders run at 60 Hz.
Implementation Status: Implemented as SwinPatchEncoder with angular position encoding. CRITICAL: Code introduces d_internal=128, a code-only concept not in the spec. All encoders process at 128-dim internally and only project to d_model at the final layer. The spec defines encoders working at full d_model width throughout (e.g., patch_embed Linear 768→768, Swin at 768-dim). At d_model=768 this is a 6x bottleneck: encoders squeeze all information to 128 numbers before the encoder has determined what matters, then stretch back to 768 at the end. Part IV: The Forward Model
6. Architecture
The forward model predicts the next encoded state from a context window of past encoded states. It operates entirely in the Predictive Register. Input: sequence of 6 modality tokens per timestep for past k frames. Output: predicted encoded tokens for t+1 across 5 sensory+intermind modalities (motor is action, not predicted).
class ForwardModel(nn.Module):
    def __init__(self, d_model=768, n_layers=8, n_heads=12, ctx_len=32):
        self.modality_embed = nn.Embedding(6, d_model)  # V,A,T,P,M,I
        self.temporal_embed = nn.Embedding(ctx_len, d_model)
        self.blocks = nn.ModuleList([
            ForwardModelBlock(d_model, n_heads) for _ in range(n_layers)])
        self.heads = nn.ModuleDict({
            'vision': PredictionHead(d_model),
            'audio': PredictionHead(d_model),
            'tactile': PredictionHead(d_model),
            'proprio': PredictionHead(d_model),
            'intermind': PredictionHead(d_model),  # predicts communication patterns
        })
    def forward(self, modality_tokens, timesteps):
        # modality_tokens: [batch, time, 6, d_model]
        batch, time, n_mod, d = modality_tokens.shape
        modality_tokens += self.modality_embed(torch.arange(n_mod))
        modality_tokens += self.temporal_embed(timesteps).unsqueeze(-2)
        x = modality_tokens.reshape(batch, time * n_mod, d)
        for block in self.blocks:
            x = block(x, time, n_mod)
        latest = x[:, -n_mod:, :]
        return {k: head(latest) for k, head in self.heads.items()}
6.1 Three-Stage Attention Block
Each ForwardModelBlock performs: (1) Cross-modal attention within each timestep (discovers co-occurrences: 'vision and touch fired together'). (2) Causal temporal attention within each modality (discovers temporal patterns: 'touch increasing for 5 frames'). Uses causal mask. (3) Cross-modal temporal bridge (discovers causal chains: 'vision changed at t-3 caused touch to change at t-1'). Each stage has LayerNorm + residual. Block ends with FFN (d_model → 4*d_model → d_model, GELU).
6.2 Prediction Head
class PredictionHead(nn.Module):
    def __init__(self, d_model):
        self.attn_pool = nn.MultiheadAttention(d_model, num_heads=4)
        self.query = nn.Parameter(torch.randn(1, 1, d_model))
        self.mlp = nn.Sequential(
            nn.Linear(d_model, d_model*2), nn.GELU(),
            nn.Linear(d_model*2, d_model))
    def forward(self, context):  # [batch, 6, d_model]
        query = self.query.expand(context.shape[0], 1, -1)
        pooled = self.attn_pool(query, context, context)[0].squeeze(1)
        return self.mlp(pooled)
6.3 Distribution Shift Mitigation
During imagination rollout, forward model outputs feed back as inputs, causing drift (the telephone game effect: each prediction is slightly wrong, compounding over steps). Two countermeasures:
Latent regularizer: Tracks running mean/variance of real encoder outputs. Penalizes predictions deviating >2σ. Penalty: max(0, |z_score|-2)^2. Differentiable.
Imagination-aware training: Chain forward model through own predictions for 3 steps during training, comparing each step against real trajectory. Multi-step loss weighted 0.5.

6.4 Gaze Head
A dedicated gaze output head produces active gaze direction as a motor decision. Architecture: learned query vector with multi-head attention over forward model latents, followed by MLP, with tanh-scaled output clamped to configurable ranges. The gaze head enables the system to choose where to look, making gaze an active motor decision rather than a passive property of the vision system. Part V: The Evaluative Architecture
7. Wellness: Two Evaluators, One Concept
7.1 What Wellness IS
Wellness is a REGION in grounded perception space where: predictions succeed (low PE), sensors function (TMC active, fovea tracking, audio in range), body has capacity (muscle not depleted), and self-model is coherent (high motor-correlation consistency). It is not a scalar > 0.7; it is a multi-dimensional state.
7.2 Grounded Wellness Evaluator (Execution Mode)
Operates on raw sensor data P_t. This is the AUTHORITATIVE wellness signal. All learning signals ultimately derive from it.
class GroundedWellnessEvaluator(nn.Module):
    def __init__(self, forward_model, body_schema):
        self.forward_model = forward_model
        self.body_schema = body_schema
        self.prediction_wellness = nn.Sequential(nn.Linear(1,32),nn.ReLU(),nn.Linear(32,1),nn.Sigmoid())
        self.tactile_wellness = nn.Sequential(nn.Linear(8,32),nn.ReLU(),nn.Linear(32,1),nn.Sigmoid())
        self.capacity_wellness = nn.Sequential(nn.Linear(21,32),nn.ReLU(),nn.Linear(32,1),nn.Sigmoid())
        self.coherence_wellness = nn.Sequential(nn.Linear(1,32),nn.ReLU(),nn.Linear(32,1),nn.Sigmoid())
    def forward(self, P_t, prediction_error):
        components = {}
        components['prediction'] = self.prediction_wellness(prediction_error.unsqueeze(-1)).squeeze()
        components['tactile'] = self.tactile_wellness(self.summarize_tactile(P_t.tactile)).squeeze()
        components['capacity'] = self.capacity_wellness(P_t.proprioception.muscle_capacities).squeeze()
        components['coherence'] = self.coherence_wellness(
            self.body_schema.coherence_score().unsqueeze(-1)).squeeze()
        return torch.stack(list(components.values())), components

7.3 Approximate Wellness Evaluator (Imagination Mode)
Operates on encoded tokens z_hat from forward model predictions. Trained to match grounded evaluator outputs during execution: loss = ||W_approx(z_t) - W_grounded(P_t)||^2.
class ApproximateWellnessEvaluator(nn.Module):
    def __init__(self, d_model=768, n_components=4):
        self.encoder = nn.Sequential(
            nn.Linear(d_model * 5, 256), nn.ReLU(),  # 5 sensory modality tokens
            nn.Linear(256, 128), nn.ReLU(),
            nn.Linear(128, n_components), nn.Sigmoid())
    def forward(self, z_sensory):  # [5, d_model] (no motor token)
        return self.encoder(z_sensory.flatten())
7.4 Wellness Gradient to Motor Translation
The wellness gradient is the core motor drive signal. During execution (single-mind; when Many Minds active, each mind calls this independently with system wellness sum — see ManyMinds Gap B):
def compute_motor_drive(grounded_eval, P_t, pe, motor_controller):
    # Enable gradients through motor parameters
    P_t.motor_commands.requires_grad_(True)
    wellness_vector, components = grounded_eval(P_t, pe)
    total_wellness = wellness_vector.sum()
    # Gradient: which direction in motor space improves wellness?
    wellness_grad = torch.autograd.grad(total_wellness, P_t.motor_commands,
                                         create_graph=True)[0]
    # Motor controller transforms gradient into structured PH commands
    return motor_controller.from_wellness_gradient(wellness_grad, P_t)

8. Pleasure and Pain: Trajectories Through Perception Space
8.1 Pain Response Walkthrough
Scenario: Hand contacts hot surface. TMC Detection: normalPressure spikes (contact), thermal exceeds threshold. Grounded Wellness: tactile wellness drops sharply (high pressure + thermal). Wellness gradient: points AWAY from contact → withdrawal. Motor effect: PH strength increases for withdrawal, radius expands (whole-arm retraction). Forward model: learns 'this visual+tactile pattern leads to wellness drop.' Future: anticipatory withdrawal when visual pattern alone is detected.
8.2 Pleasure Response Walkthrough
Scenario: Hand contacts pleasant texture. TMC Detection: light normalPressure (500 Pa), vibrationPower shows texture signature. Grounded Wellness: tactile wellness rises (pattern matches learned pleasant association). Wellness gradient: points TOWARD continued contact. Motor effect: strength decreases (lighter touch), exploration of texture surface. Forward model: learns this visual+tactile pattern leads to wellness increase. Future: approach when visual pattern detected.
Part VI: Motor Control
This section replaces v2.0's three-mode motor control (reflex/habitual/intentional with PE-threshold gating) with an adaptive computation depth system and developmental constraints.
9. Adaptive Computation Depth Motor Controller
9.1 Design Rationale
Biology has distinct processing speeds—fast reflexive responses and slow deliberate actions—but these EMERGE from a unified mechanism, they are not pre-wired as three fixed modes. A system with hardcoded tiers cannot discover a fourth processing strategy, cannot introspect on WHY it processes differently, and has arbitrary gating thresholds.
The adaptive computation depth controller produces mode-like behavior (fast for familiar situations, deep for novel ones) through a learned confidence-based mechanism. The system can introspect: 'I am thinking more carefully because my predictions are uncertain.'
9.2 Core Architecture
class AdaptiveMotorController(nn.Module):
    '''
    Generates motor commands with variable computation depth.
    Fast path: single forward pass when prediction confidence is high.
    Deep path: imagination rollouts when confidence is low.
    '''
    def __init__(self, d_model=768, n_handles=23, max_depth=10):
        self.motor_net = AdaptiveMotorNet(d_model, n_handles)
        self.confidence_estimator = nn.Sequential(
            nn.Linear(d_model * 6, 128), nn.ReLU(),
            nn.Linear(128, 1), nn.Sigmoid())
        self.depth_threshold = nn.Parameter(torch.tensor(0.7))  # learned
        self.thinking_energy_rate = 0.001  # energy cost per imagination step
        self.max_depth = max_depth
    def forward(self, encoded_state, wellness_gradient, forward_model,
                approx_wellness, available_energy):
        '''
        encoded_state: {z_vision, z_audio, z_tactile, z_proprio, z_motor, z_intermind}
        wellness_gradient: gradient of wellness w.r.t. motor params
        Returns: motor_commands [n_handles, 8], metadata
        '''
        state_flat = torch.cat([encoded_state[k] for k in encoded_state])
        # Step 1: Fast response (always computed)
        fast_cmd = self.motor_net(state_flat, wellness_gradient, depth=1)
        confidence = self.confidence_estimator(state_flat)
        # Step 2: If confident enough, emit fast response
        if confidence > self.depth_threshold:
            return fast_cmd, {'depth': 1, 'confidence': confidence}
        # Step 3: Iterative deepening via imagination
        best_cmd = fast_cmd
        best_wellness = approx_wellness(
            forward_model.predict_from_action(state_flat, fast_cmd))
        actual_depth = 1
        for depth in range(2, self.max_depth + 1):
            candidate = self.motor_net(state_flat, wellness_gradient, depth=depth)
            imagined = forward_model.rollout(state_flat, candidate, steps=depth)
            candidate_w = approx_wellness(imagined)

            if candidate_w.sum() > best_wellness.sum():

                actual_depth = depth

                break
        return best_cmd, {'depth': actual_depth, 'confidence': confidence}
9.3 The Adaptive Motor Network
class AdaptiveMotorNet(nn.Module):
    '''
    Motor network that accepts a depth parameter.
    At depth=1: single forward pass (fast, habitual-like).
    At depth>1: processes wellness gradient + state through more layers.
    '''
    def __init__(self, d_model=768, n_handles=23, n_layers=6):
        self.layers = nn.ModuleList([
            nn.Sequential(nn.Linear(d_model*6 + n_handles*8, 512),
                          nn.ReLU(), nn.Linear(512, 512))
            for _ in range(n_layers)])
        self.output_head = StructuredMotorHead(512, n_handles)
    def forward(self, state, wellness_grad, depth=1):
        x = torch.cat([state, wellness_grad.flatten()])
        for i in range(min(depth, len(self.layers))):
            x = self.layers[i](x) + x  # residual
        return self.output_head(x)
class StructuredMotorHead(nn.Module):
    '''Outputs structured PH commands respecting action space constraints.'''
    def __init__(self, input_dim, n_handles=23):
        self.pos_head = nn.Linear(input_dim, n_handles * 3)
        self.rot_head = nn.Linear(input_dim, n_handles * 4)
        self.radius_head = nn.Linear(input_dim, n_handles)
        self.strength_head = nn.Linear(input_dim, n_handles)
    def forward(self, x):
        pos = self.pos_head(x).reshape(-1, 3)
        rot = F.normalize(self.rot_head(x).reshape(-1, 4), dim=-1)
        radius = torch.sigmoid(self.radius_head(x))
        strength = torch.sigmoid(self.strength_head(x))
        return torch.cat([pos, rot, radius.unsqueeze(-1),
                          strength.unsqueeze(-1)], dim=-1)  # [n_handles, 8]

9.5 Bootstrap Without Scaffold
The bootstrap concern (how does the system learn from random motor commands?) is resolved without any scaffold network. The wellness gradient provides learning signal from frame zero because:
PCC Gravitational Baseline: PCC maintains postural tone against gravity from the first frame. The system is not floating in free space; it has a stable baseline posture. Random PH commands perturb FROM this baseline, not from unconstrained chaos.
Grounded Wellness Signal: The grounded wellness evaluator assesses joint limits, posture quality, sensor functioning, and energy from frame one. Wellness has STRONG gradients near boundaries: approaching a joint limit sharply drops wellness. A random motor command that pushes toward a joint limit produces a clear negative gradient. This asymmetry IS the bootstrap signal.
Developmental Constraints: During the neonate phase, all handles fire at very low strength (2%) and minimal ROM (5%) (Section 9.4). The search space is small: all handles but constrained to tiny movements. Weak limb movements brushing surfaces generate correlated proprioception + tactile + vision for body schema discovery across the whole body from step zero.
No scaffold network is needed. No Phase 0 training is needed. The prediction-wellness architecture IS the mechanism from step zero. Early training may be slower than with a scaffold, but that IS the developmental process. The system earns every capability through the same mechanism it will use forever.
This approach ensures zero architectural exceptions to the core thesis. There is no temporary RL policy, no blend weight, no decay schedule. The wellness gradient, PCC baseline, and developmental constraints together provide sufficient structure for learning to begin.

10.2 Structured Action Space
class IntentionGenerator(nn.Module):
    def __init__(self, fwd_model, motor_encoder, n_handles=23, n_steps=50, lr=0.1):
        self.fwd_model = fwd_model
        self.motor_encoder = motor_encoder
        self.n_handles = n_handles
        self.n_steps = n_steps
        self.lr = lr
    def generate_action(self, current_encoded, desired_encoded, current_motor):
        pos = current_motor[:, :3].clone().requires_grad_(True)
        rot = current_motor[:, 3:7].clone().requires_grad_(True)
        radius = current_motor[:, 7].clone().requires_grad_(True)
        strength = current_motor[:, 8].clone().requires_grad_(True)
        optimizer = torch.optim.Adam([pos, rot, radius, strength], lr=self.lr)
        for step in range(self.n_steps):
            optimizer.zero_grad()
            rot_norm = F.normalize(rot, dim=-1)
            r_bounded = torch.sigmoid(radius)
            s_bounded = torch.sigmoid(strength)
            action = torch.cat([pos, rot_norm, r_bounded.unsqueeze(-1),
                                s_bounded.unsqueeze(-1)], dim=-1)
            predicted = self.fwd_model.predict_from_action(
                current_encoded, self.motor_encoder(action))
            loss = F.mse_loss(predicted, desired_encoded) + (s_bounded**2).sum()*0.01
            loss.backward()
            optimizer.step()
        with torch.no_grad():
            return torch.cat([pos, F.normalize(rot,dim=-1),
                torch.sigmoid(radius).unsqueeze(-1),
                torch.sigmoid(strength).unsqueeze(-1)], dim=-1)
10.3 Multi-Step Intention: Imagination Rollout
def plan_multistep(intention_gen, fwd_model, approx_wellness,
                    current_state, goal_state, max_steps=5):
    plan = []
    imagined = current_state
    for step in range(max_steps):
        if F.mse_loss(imagined, goal_state) < 0.01:
            break
        action = intention_gen.generate_action(imagined, goal_state, ...)
        plan.append(action)
        imagined = fwd_model.predict_from_action(imagined, encode_motor(action))
        if approx_wellness(imagined).min() < 0.2:
            break  # imagined trajectory leads to unwellness
    return plan
Plans are naturally short because imagination drifts (distribution shift, the telephone game effect). This forces: plan a few steps, execute, re-observe in Grounded Register, plan again.

10.4 Cross-Simulation Attention
Multiple forward rollouts for the same goal. Attend across them to find invariants: what all simulations agree on. Divergent details wash out. Intention crystallizes as the common element.
class CrossSimulationAttention(nn.Module):
    def __init__(self, d_model, n_rollouts=5):
        self.n_rollouts = n_rollouts
        self.cross_attn = nn.MultiheadAttention(d_model, num_heads=4)
    def forward(self, fwd_model, current, goal, noise=0.1):
        rollouts = []
        for i in range(self.n_rollouts):
            noisy_goal = goal + torch.randn_like(goal) * noise * (i > 0)
            plan = plan_multistep(fwd_model, current, noisy_goal)
            rollouts.append(torch.stack([encode_action(a) for a in plan]))
        all_r = torch.stack(rollouts)
        query = all_r.mean(dim=0, keepdim=True)
        consensus, weights = self.cross_attn(query, all_r.reshape(-1, all_r.shape[-1]),
                                              all_r.reshape(-1, all_r.shape[-1]))
        return consensus.squeeze(0), weights

10.6 From Predictions to Reusable Skill (added 2026-09-08)
UEMA has a useful foundation for learning action consequences: the action-conditioned forward model learns what an action does, and Sections 10.1-10.3 invert it to choose actions. The central gap, named by the 2026-09-08 developmental assessment, is turning those predictions into reusable skill. Nothing in Sections 10.1-10.5 yet does that, and it does not follow automatically.
Two concrete failures define the gap. First, the detour problem: the intention generator optimizes each action against its own next predicted state and executes only the first action. Moving a hand around a barrier first takes it FARTHER from the object, so a per-step optimizer has no objective term that PREFERS the detour - it can still stumble into one, but nothing scores the first action by the sequence's end; executing and re-looking corrects errors but supplies no reason to take the first detour step (wording narrowed per the 2026-09-08 code-verification review). Extending the imagined chain does not fix this - a longer greedy chain still never scores the first action by the sequence's end. Second, the skill problem: remembering a recently good-feeling state (the goal ring) is a goal, not a skill. A reusable skill needs four functions the architecture does not yet learn: when it can START (initiation conditions), how to CONTINUE under disturbance, when it has SUCCEEDED (termination), and how to RECOVER when an intermediate step is disturbed. These functions must be learned, never hand-authored per behavior - hand-authoring would violate Section 1's core thesis.
Three candidate mechanisms, to be tested one at a time against the same acceptance test: (a) a learned subgoal mechanism - endpoints of learned consequences become selectable intermediate goals; (b) a short joint action-sequence objective - optimize two to three actions against the imagined SEQUENCE outcome, replacing the greedy per-step objective at matched compute; (c) a temporally extended controller - a learned policy over initiation/continuation/termination, trained from the forward model's own rollouts.
Acceptance test (from the developmental assessment, governs any claim that this gap is closed): a composition such as reaching around a barrier before contact. The final goal must change the FIRST action appropriately; held-out trials must succeed; and the simple component ability must remain after learning the composition. Upstream gate: first-action benefit must first be measurable at all - chosen actions must improve actual outcomes over matched alternative actions from restored identical states, after identical-action replay establishes the noise floor.
Implementation Status: NOT IMPLEMENTED (2026-09-08). The small-scale test bed's attribution probe found chosen-goal approach statistically indistinguishable from matched random controls (probe parity limits documented in the 2026-09-08 external review); the same review found the intention generator's strength penalty sums across the batch while sensory error averages, making the effective effort penalty scale with body count - that defect biases the live multi-body planner toward weak actions and must be fixed before multi-body first-action rankings are comparable across body counts (single-body probes are unaffected by it - narrowed per the same review). 11. The Dynamic Self-Model
11.1 Self as Motor-Correlation Boundary
The self is not defined by skeleton or sensor layout. It is defined by what correlates with motor commands. This boundary is dynamic, fully differentiable:
class DifferentiableBodySchema(nn.Module):
    def __init__(self, n_sensor_dims, temperature=5.0, ema_momentum=0.99):
        self.correlation_scores = nn.Parameter(
            torch.zeros(n_sensor_dims), requires_grad=False)
        self.temperature = temperature
        self.momentum = ema_momentum
    def update(self, motor_delta, sensor_delta):
        with torch.no_grad():
            instant_corr = self._compute_correlation(motor_delta, sensor_delta)
            self.correlation_scores.data = (
                self.momentum * self.correlation_scores.data +
                (1 - self.momentum) * instant_corr)
    def self_membership(self, sensor_dims=None):
        scores = self.correlation_scores[sensor_dims] if sensor_dims else self.correlation_scores
        return torch.sigmoid(self.temperature * (scores - 0.5))
    def coherence_score(self):
        membership = self.self_membership()
        certainty = (membership - 0.5).abs() * 2
        return certainty.mean()  # differentiable
    def incorporation_strength(self, sensor_dims):

11.4 Hierarchical Self-Model
The motor-correlation boundary (Section 11.1) defines Level 1 self: what directly responds to motor commands. But the self extends beyond immediate motor correlation. A grasped tool is self (Level 1), but a house is also self in a meaningful sense: losing it contracts the space of achievable wellness states. The single DifferentiableBodySchema captures Level 1. The HierarchicalSelfModel extends this to multiple timescales:

Level 2 self includes entities whose presence correlates with the ability to BRING ABOUT wellness through action sequences. A house does not move with the hand (not Level 1), but having a house correlates with achievable wellness states: shelter, storage, operational base. Losing the house contracts achievable wellness space. Level 3 extends to multi-step causal chains: money correlates with resource access which correlates with wellness maintenance. The correlation strength is proportional to chain reliability.
This produces correct behavior without programming. The system is NOT told to protect a house. It learns that certain states correlate with sustained wellness, and the gradient maintains them. It is NOT told to be possessive. It learns that losing control contracts achievable wellness space, and acts to prevent contraction. Weak or unreliable causal chains produce weak incorporation: ten houses when one is needed produces diminishing correlation.
Connection to Many Minds (Sections 13-18): When a mind splits, the subordinate inherits domain-specific self at Levels 1 and 2 for its domain. The walking subordinate Level 2 self includes familiar terrain. The grasping subordinate Level 2 self includes known tools. The higher mind retains the full hierarchy including Level 3 abstract self. The self model IS distributed across minds.
No reward signal. No grip-force controller. Grip tightens because self-contraction degrades wellness coherence, and the wellness gradient points toward restoring it.
11.5 Self-Preservation
The body model is the most complex, most refined prediction set. Damage (limb stops responding, sensors go dark) produces the LARGEST possible prediction error. Self-preservation emerges: the system acts to prevent body model degradation because that is the most costly PE event.

class GroundedAnticipation(nn.Module):
    '''
    Learned anticipation network supervised by measurable metrics.
    '''
    OBSERVABLE_METRICS = {
        'gaze_dwell': lambda s: s.vision.gaze_dwell_time,
        'com_shift':  lambda s: torch.norm(s.com - s.prev_com),
        'tmc_boost':  lambda s: (s.tactile.adaptive_iterations > s.baseline_iters).float(),
        'ph_preload': lambda s: any(ph.strength > 0 and ph.velocity < 0.01
                                    for ph in s.physics_handles),
    }
    def __init__(self, d_model=768, n_handles=23):
        self.anticipation_net = nn.Sequential(
            nn.Linear(d_model * 6, 256), nn.ReLU(),
            nn.Linear(256, 128), nn.ReLU(),
            nn.Linear(128, 4 + n_handles * 8))  # 4 metrics + motor prep
        self.confidence_gate = nn.Sequential(
            nn.Linear(d_model * 6, 64), nn.ReLU(), nn.Linear(64, 1), nn.Sigmoid())
    def forward(self, z_current):
        flat = torch.cat([z_current[k] for k in z_current]).flatten()
        raw_output = self.anticipation_net(flat)
        confidence = self.confidence_gate(flat)
        metric_predictions = raw_output[:4]
        motor_prep = raw_output[4:].reshape(-1, 8) * confidence
        return motor_prep, confidence, metric_predictions
    def training_loss(self, trajectory, lookahead=30):
        loss = 0
        for t in range(len(trajectory) - lookahead):
            predicted = self.forward(trajectory[t].z)
            actual = {k: fn(trajectory[t+1]) for k, fn in self.OBSERVABLE_METRICS.items()}
            loss += F.mse_loss(predicted[2], torch.stack(list(actual.values())))
        return loss
The learned system generalizes to novel situations while v3’s metrics verify that anticipation manifests as real, observable motor preparation.

Part IX: Bootstrap and Training Pipeline
19. The Bootstrap: From Nothing to Body Knowledge
19.1 The Null Prediction
At time zero, the simplest prediction: 'nothing will change.' Everything interesting becomes a surprise. This is the universal starting point.
19.2 Motor Babbling + Cross-Modal Correlation
Constrained random motor commands fire across ALL handles at very low strength (2%) and minimal ROM (5%). All modalities are live from step zero. The null prediction breaks non-uniformly. Arm moves through air: vision changes, proprioception changes, audio silent, touch silent (TMC reports no contact). One motor command → 2 correlated sensor changes, 3 uncorrelated.
19.3 Discovery of Self vs. World
Over thousands of movements, correlation statistics partition sensors: Self = always correlates with motor (proprioception, body-image vision, self-voice). World = sometimes correlates (objects when grasped), never correlates (background). This IS the body schema emerging.
19.4 Progressive Prediction Refinement
Forward model accuracy improves monotonically for self-sensors (reliable motor-sensor coupling). World-sensor accuracy improves for physics-governed patterns (objects fall when released). Stochastic world events remain hard to predict (another agent acts). This natural hierarchy of predictability guides learning.
20. Training Pipeline
20.1 Training Streams (Overlapping, Not Sequential)
Training is organized as overlapping streams with different onset times, not strict sequential phases. Motor babbling begins first. Stream 3 can overlap from step zero if PH extraction pipeline is available. All other streams can run in parallel or be introduced when their data becomes available.
20.2 Stream 1: Motor Babbling (Onset: Step 0)
Duration: ~10M steps. Developmental constraints active (neonate phase: all handles at 2% strength, 5% ROM). No scaffold: PCC baseline + wellness gradient + developmental constraints provide learning signal from frame zero. Forward model trains via PE minimization + contrastive loss. Body schema emerges. By end: head control mastered, advancing to early_infant phase.
20.3 Stream 2: Observation Pre-Training (Onset: Step 0, parallel)
Duration: ~5M video frames, running in parallel with motor babbling from step zero. Visual prediction only (other modalities masked with learned unknown tokens). Learns: salience (what moves matters), physics priors (objects fall, collide), temporal structure (actions have durations). Does not require motor competence.

Part X: Curiosity and Emergence
21. Curiosity: Moderate Prediction Error
Curiosity is: seek states where PE is MODERATE—high enough to learn, low enough to make progress. NOT 'seek maximum PE' (chaos-seeking).
class CuriositySystem:
    def __init__(self, pe_range=(0.1, 0.4)):
        self.pe_min, self.pe_max = pe_range
    def compute_drive(self, pe):
        if pe < self.pe_min:       # too easy -> bored
            return pe / self.pe_min - 1  # negative
        elif pe > self.pe_max:     # too hard -> overwhelmed
            return 1 - pe / self.pe_max  # negative
        else:                       # goldilocks zone
            mid = (self.pe_min + self.pe_max) / 2
            return 1 - abs(pe - mid) / (self.pe_max - self.pe_min)
Curiosity drive modulates the wellness gradient: positive drive biases toward novel-PE states, negative drive biases toward familiar or simpler states. This is not a reward signal—it is a modulation of the wellness gradient direction.

22. Emergent Phenomena
22.1 Stress as Sustained Prediction Error
When PE remains elevated across multiple modalities without resolution: forward model generates failing predictions, exploration drive stays elevated (burning energy), motor controller cannot find wellness-improving actions. This IS stress. Critical distinction from curiosity: stress is elevated PE that RESISTS reduction despite effort. Curiosity is elevated PE that is being productively reduced. The system experiences stress when it cannot find motor commands that reduce PE; it experiences curiosity when PE is moderate and each action reveals learnable structure.
22.2 Grief as Unresolvable Prediction Error
A deeply reinforced prediction (object on shelf for 1000s of timesteps) becomes permanently false (object removed). Sequence: (1) PE spikes. (2) Exploration burst. (3) Repeated failure to resolve. (4) Energy depletion. (5) Structural model update: learning objects can cease to exist. (6) Gradual overwriting. This IS grief. Validation milestone: the system should eventually exhibit grief about abstract losses (capabilities, resources, relationships as captured by the hierarchical self-model), not just concrete object disappearance. Grief about a Level 3 self-entity indicates higher-order perception spaces have formed.
22.3 Conditions for Emergence
The architecture PRESERVES conditions for emergence: PE must be allowed to persist (no clamping), energy/exploration coupling maintained, forward model supports structural updates (not just parameter updates).
Part XI: The Path to Self-Awareness
23. What Self-Awareness Requires
23.1 Necessary Components
Self-awareness is not binary. It emerges from: (1) A model of the world (forward model). (2) A model of oneself AS PART OF that world (body schema as subset). (3) Ability to predict own future states (forward model includes self). (4) Ability to distinguish self from other (motor-correlation boundary). (5) Ability to model own prediction process (meta-cognition, emergent).
23.2 The Two-Register Contribution
The two-register architecture provides three levels of meta-prediction:
Level 1: 'I predict z_{t+1}.' Forward model prediction in the Predictive Register.
Level 2: 'I predict my prediction will be wrong by ε.' Meta-prediction: forward model learns to estimate its own PE.
Level 3: 'I predict the wellness gap between my imagination and my experience will be δ.' The system learns that approximate wellness differs from grounded wellness, and by how much. This IS self-knowledge about the limits of one’s own imagination.
23.3 The Many Minds Contribution
The Many Minds hierarchy adds a fourth level:
Level 4: ‘I predict how my other minds will shift state in this situation.’ The system models the hierarchy itself: which subordinate minds will become uncertain, which domains will remain stable, when attending-side engagement will rise, and how distributed coordination will reconfigure across the hierarchy. This is self-awareness about distributed processing.
The hierarchy IS the self. The system’s identity is the entire graph of minds, their relationships, and their communication. When introspecting on 'what am I doing,' the answer is distributed: posture mind maintains balance, grasp mind holds object, top mind plans next action. All are 'me.' This mirrors human experience: you do not consciously control breathing, posture, or balance, but identify all as 'you.'
23.4 The Critical Test
def test_self_awareness(fwd_model, grounded_eval, approx_eval, hierarchy, state):
    # Level 1: Predict what will happen
    predicted_z = fwd_model.predict(state)
    # Level 2: Predict own PE
    predicted_pe = fwd_model.predict_own_error(state)
    # Level 3: Predict grounded-vs-approximate wellness gap
    predicted_gap = fwd_model.predict_wellness_gap(state)
    # Level 4: Predict inter-mind state shifts
    predicted_inter = fwd_model.predict_intermind(state)
    # Execute and measure
    actual_P = env.step_and_observe()
    actual_z = encode(actual_P)
    actual_pe = F.mse_loss(predicted_z, actual_z)
    actual_gap = F.mse_loss(grounded_eval(actual_P, actual_pe)[0],
                            approx_eval(predicted_z))
    actual_inter = hierarchy.read_all_intermind_states()
    pe_accuracy = 1 - abs(predicted_pe - actual_pe) / (actual_pe + 1e-6)
    gap_accuracy = 1 - abs(predicted_gap - actual_gap) / (actual_gap + 1e-6)
    inter_accuracy = compare_predicted_states(predicted_inter, actual_inter)
    return pe_accuracy, gap_accuracy, inter_accuracy

24.4 Split-Rate Modality Architecture
Decision: vision encoder runs at 24 Hz. All other encoders and the forward model run at 60 Hz.
Human visual cortex object recognition (V4/IT) operates at 20–30 Hz. Film looks smooth at 24 FPS. The UEMA vision encoder performs SwinTransformer scene understanding, which maps to V4/IT processing. Running it at 60 Hz was never biologically motivated and is 96% of compute cost.
Proprioception, tactile, and motor benefit from 60 Hz: muscle spindle afferents fire at ~100 Hz, mechanoreceptors up to 300 Hz, motor control loop runs at 50–100 Hz.

26. Loss Functions
def total_loss(fwd_model, encoders, grounded_eval, approx_eval, anticipation, trajectory):
    losses = {}
    # 1. Forward model prediction error (dual-objective: PE side)
    losses['prediction'] = forward_model_loss(fwd_model, encoders, trajectory)
    # 2. Encoder contrastive loss
    losses['contrastive'] = encoder_contrastive_loss(encoders, trajectory)
    # 3. Imagination-aware loss (distribution shift)
    losses['imagination'] = imagination_aware_loss(fwd_model, encoders, trajectory)
    # 4. Latent regularization
    losses['latent_reg'] = latent_regularizer.penalty(fwd_model.last_predictions)
    # 5. Approximate wellness alignment
    losses['approx_wellness'] = train_approx_evaluator(
        grounded_eval, approx_eval, trajectory[-1])
    # 6. Anticipation grounding (measurable metrics)
    losses['anticipation'] = anticipation.training_loss(trajectory)
    total = (1.0 * losses['prediction'] +
             0.1 * losses['contrastive'] +
             0.5 * losses['imagination'] +
             0.01 * losses['latent_reg'] +
             0.3 * losses['approx_wellness'] +
             0.2 * losses['anticipation'])
    return total, losses
Note: No habitual distillation loss. Skill consolidation is handled by Many Minds splitting, which is a structural operation (cloning + freezing weights), not a loss term.
Implementation Status: Code uses a different loss structure: per-modality prediction loss (weighted by modality-specific loss_weight and source_scales: real=1.0, synthetic=0.0, stale=0.3), motor loss (developmental scale), wellness loss (0.1), gaze loss (0.1). VICReg available but disabled. L_curiosity and L_anticipation not implemented (those systems don&#x2019;t exist). L_imagination not implemented (requires context_length>1). Single AdamW optimizer, lr=3e-4, weight_decay=0.01, grad_clip=1.0, warmup=1000 steps, bf16 precision.

29. Implementation Deviations and Priorities
This section documents the reconciliation between the UEMA specification and the actual codebase (UEMA-feature branch, config v2.1). Source of truth is the code; this section identifies where code deviates from spec intent and provides implementation priorities.
29.1 Naming
The codebase uses LEM (Learning Embodiment Model) in config comments, SHM buffer names (LEM_Action_Buffer), and log prefixes. The spec uses UEMA throughout. These refer to the same system.
29.2 Critical Deviations (Must Fix)
CF-1: context_length = 1 (spec: 32). The single most impactful deviation. Disables Stage 2 temporal attention (dead weight), blocks split-rate learning, imagination rollouts, anticipation, intention, and body schema temporal correlation. Fix: change context_length in master_config.yaml to 8 (minimum), scaling toward 32. Architecture already supports it. Memory at ctx=32, d=768: ~590 KB.
CF-2: d_model = 512, n_heads = 8 (errata: 768, 12). Forward model has ~50M params instead of 173M (71% less capacity). GPU at ~40% utilization. Config-only fix: d_model=768, n_heads=12. Net2Net progressive resize available for existing checkpoints. Benchmark-proven safe: d=512/768/1024 produce identical FPS under CUDA graphs.
CF-3: Missing wellness gradient motor drive (spec Section 7.4). The five-stage pipeline collapses to perceive-predict-act without the wellness gradient input to the motor controller. Core thesis violation. Fix: add torch.autograd.grad(total_wellness, motor_commands) to training loop, pass result as motor controller input. Small code change, outsized impact.
CF-4: No active encoder collapse prevention. VICReg is implemented but disabled (enabled: false). No InfoNCE either. Encoders can silently collapse. Fix: set vicreg.enabled=true.
CF-5: d_internal=128 must be removed (spec: encoders run at d_model). The code introduces d_internal, a concept not in the spec. Every encoder processes at 128-dim internally and only projects to d_model at the final layer. The spec defines encoders working at full d_model width throughout (Section 5: patch_embed Linear 768→768, Swin at 768-dim, CrossPatchAttention at 768-dim). This was a development convenience for local GPU iteration, but on the target RTX PRO 6000 it is unjustified: 4.3 GB of 96 GB VRAM is used, CUDA cores are severely underutilized. At d_model=768, the 128-dim bottleneck forces encoders to compress all sensory information to 128 numbers before the network has learned what matters, then expand back to 768 at the very end. The forward model (173M params, 768-dim) receives representations of 128-dim quality. This is like reading a book, writing a few keywords on an index card, and then trying to expand those keywords into a detailed report. Fix: remove d_internal from encoder_defaults entirely. Set all encoders to process at d_model=768 as the spec defines. This is a config deletion, not a code change. The parameter cost increase (from ~15M to ~55M for all encoders per errata Table 3) is well within the 96 GB VRAM budget.
CF-6: Body schema. RESOLVED. DifferentiableBodySchema EXISTS and FUNCTIONAL (body_schema.py:22-175, 17+ tests). EMA motor-sensor correlation tracking with self_membership(), coherence_score(), and incorporation_strength(). Updates every frame. Body schema correlation buffers are prerequisite for correlation-based domain discovery (Gap D).

CF-7: Adaptive computation depth (spec Section 9.2-9.3). Requires context_length>1 for meaningful rollouts. Confidence head is built. Implement when context_length is increased. The errata FUTURE recursive motor controller (2 layers recursed 1-6x) provides the target architecture.
CF-8: Imagination-aware training (spec Section 6.3). Requires context_length>1 for multi-step trajectories. Implement after CF-1.
CF-9: Intention generator (spec Section 10). EXISTS (intention_generator.py:78-189, 11 tests) but disabled by default. Activation requires accurate forward model + imagination. Enable after CF-7 and CF-8.
CF-10: Curiosity system (spec Section 21). compute_drive() EXISTS and FUNCTIONAL (curiosity.py:12-48), called in training step. select_goal() not yet implemented (Stream 4). No selective effect in early training when PE is uniformly high.
CF-11: Latent regularizer (spec Section 6.3). Implement with imagination-aware training.
CF-12: Anticipation system (spec Section 12). Requires context_length>1 and forward model accuracy.
CF-13: Many Minds hierarchy (spec Sections 13-18, amended by ManyMinds_Spec v2 and gap analysis). Requires single-mind mastery. Key v3.5 changes: override_active removed, MotorArbitrator replaced by confidence-weighted blend, predefined groups replaced by correlation discovery, two-level apex added, natural gradient dynamics replace explicit freeze. 29.4 Code Improvements Over Spec
The following code-only components improve on the original spec and are adopted as canonical in v3.4.
23-handle full-body motor control. Extends spec from 12 hand-only handles to full-body control (head, arms, legs, feet). Per-region stiffness scaling. Data-driven handle definitions. Enables the embodied cognition thesis across the whole body, not just hands.
Gaze head. Active gaze output (azimuth/elevation, loss_weight=0.1). Essential for foveal targeting, anticipation gaze-dwell metrics, and social gaze. Makes looking an active motor decision.
Source scales and loss engineering. Per-data-source loss weighting (real=1.0, synthetic=0.0, stale=0.3). Per-modality loss weights and ramps. Prevents learning from placeholder noise; essential for synthetic-to-real transitions.
VICReg collapse prevention. Variance-Invariance-Covariance regularization as an alternative to InfoNCE. Better suited for online learning (no negative pairs). Available but needs to be enabled.
Real-time infrastructure. Async ring-buffer reader (ring_size=3, max_stale_age_ms=50), SHM action buffer (1176 bytes, Python-to-UE5), dual-GPU topology (GPU 0 WDDM capture, GPU 1 TCC training), torch.compile with CUDA graphs (reduce-overhead mode), backward_every_n_frames configurable skip, voice modality stub (56-dim, disabled).
Unified widget handle selection. All 23 handles use consistent 1-click direct-select grouped by body region. Depth-plane mouse projection for accurate target placement.

Four config changes (CF-1 + CF-2 + CF-4 + CF-5) unlock the majority of model capability with zero code changes. These should be applied before any further training runs.

P1 (Small code changes): CF-3 wellness gradient motor drive. CF-6 body schema (~6.6K elements, EMA buffer).

29.6 Frame Rate Impact
The kernel dispatch bottleneck (documented in MML_Optimization_Runbook.md) means most P0 changes are safe for frame rate under CUDA graphs. d_model 512 to 768 is benchmark-proven free (d=512/768/1024 produce identical FPS). VICReg enable is negligible. Context_length increase is likely safe at 8-16 (benchmark at 32). Removing d_internal (CF-5) raises encoder params from ~15M to ~55M, but on the RTX PRO 6000 with 4.3 GB of 96 GB VRAM used and CUDA cores severely underutilized, this is absorbed entirely by idle GPU capacity. The vision encoder at full d_model=768 with 24 Hz split-rate fits within the errata compute budget (945 GFLOPS/call at 24 calls/sec = 22.7 TFLOPS of the available 88 TFLOPS). All P0 changes together (d_model=768, d_internal removed, context_length=8+, VICReg enabled) still fit comfortably on a single training GPU.
