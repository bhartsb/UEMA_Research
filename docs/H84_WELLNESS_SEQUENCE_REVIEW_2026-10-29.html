UEMA design review · October 29, 2026 · for the project owner

Learn what led to an outcome, from a quick catch to a lasting change.

The right unit of experience is a timed history: what the body was doing, which commands actually reached it, what changed, and what followed.

Recommendation: extend UEMA's existing memory and prediction paths to learn bodily consequences over several timescales. Use attention to retrieve and combine relevant experience. Let those predictions inform intention goals and the commands used to pursue them.

Correction to my earlier answer: UEMA already has persistent memory with a recurrent network, attention and a bodily-outcome predictor. Its separate self-state path also learns from executed sequences at several horizons and retains complete windows for replay. The preserved TUNBL_u_496250_a2 branch enabled persistent memory and self learning. The 200-model-step goal ring is only one part of the system. Adding another generic memory module would miss the real question: what sequence survives, what it teaches, and where its predictions influence a choice.

1. Keep the cause, the response and the consequence in order.

A body starts leaning. Its support slips. An arm catches it. The hand experiences pressure. The body recovers. Blaming the last command for the pressure would teach the wrong lesson: the catch may have prevented a much worse impact.

Earlier condition

The body leans while its support becomes unstable.

Corrective command

The arm moves toward a supporting surface.

Brief consequence

Contact produces a pressure spike and slows the fall.

Later consequence

Support returns and useful movement is preserved.

What should be learned is conditional: from this unstable situation, this catch improved the outcome compared with not catching. From an earlier stable situation, avoiding the loss of support may be better still. Both facts can be true.

Several clocks describe the same experience.

Brief events

Preserve the order of slip, contact and pressure changes at the available sensor and command resolution. Record short peaks within an interval, not just its average. A half-second summary can hide their order.

A whole movement

Keep the coordinated sequence across seconds: gaze, support, arm and fingers can change together. Three seconds is a useful reach example, not a limit on memory or a requirement that every motion take three seconds.

Delayed effects

Link repeated effort, exposure or lost support to consequences that appear many seconds or minutes later. Preserve duration and cumulative exposure as well as the strongest event.

Long experience

Retain useful episodes and learned relationships across sessions. A recurrent summary can carry history forward, while selected records preserve evidence that can be revisited when the body or model changes.

These are overlapping views of time. They are not four scripted controllers or an infant training timetable. Exact recording rates and forecast horizons must match sensor availability, physical dynamics and the available compute.

2. Which combinations are useful, and how can each mislead us?

Commands + starting condition + later bodily changes

Use: learn how the same command affects a supported body and an already falling body differently.

Failure: remembering the command alone treats it as universally helpful or harmful.

Design: make body and scene history part of both retrieval and prediction. Keep timing and the actual applied command.

Several commands + their order + delays

Use: distinguish supporting before reaching from reaching before support exists.

Failure: an average of commands loses order; selecting only the biggest event can lose the preparation that made success possible.

Design: retain contiguous recent sequences and link their summaries to longer episodes. Include elapsed time explicitly.

Wellness level + change + duration

Use: distinguish a brief disruption, ongoing harm and stable good condition.

Failure: the derivative, meaning the rate of change, is zero during both stable wellness and sustained unwellness. Small sensor errors can also create large apparent rates over very short intervals.

Design: predict the levels of separate bodily channels over time; derive changes using actual elapsed time. Keep valid event peaks and time spent in a poor condition. Filtering must not erase the transient being learned.

Expected outcome + actual outcome

Use: identify a mistaken prediction that needs learning, such as an unexpectedly slippery surface.

Failure: predictable pain has little prediction error, but is still bad. Surprise alone is not pain or benefit.

Design: use prediction error to teach the model and inform uncertainty. Preserve the actual bodily consequence even after it becomes predictable.

Brief discomfort + later ability or recovery

Use: accept a necessary catch or a demanding movement whose later consequences are better.

Failure: immediate-comfort selection can prevent useful effort. End-state-only selection can ignore severe harm along the way.

Design: compare the path and its continuation. The forecast must include the bodily function that makes the later benefit useful.

Repeated small events + accumulated change

Use: learn that repeated load can have a delayed effect, if that effect exists in the physical model.

Failure: no single event looks important; storing only surprises discards the build-up.

Design: retain time under load and representative ordinary sequences. Do not invent fatigue or damage that the simulator does not produce.

Useful action + the harm that did not happen

Use: learn the value of maintaining support before a fall occurs.

Failure: no wellness increase is observed because prevention kept it stable.

Design: compare predicted outcomes with and without the support movement. Test those predictions in matched copied worlds when authorized. Predicted alternatives remain separate from lived evidence.

Outside event + action + outcome

Use: separate a command's effect from a moving surface or an outside disturbance.

Failure: the command that happens just before an externally caused improvement gets false credit.

Design: include observed outside changes and vary commands from matched starting states. An attention map alone cannot identify the cause.

Intended outcome + attempted sequence + actual result

Use: learn whether a route can achieve an intended outcome from the current state.

Failure: the goal label predicts success because past attempts were selected only in easy situations.

Design: include failed attempts and changed conditions. Require command-dependent forecasts, rather than letting the intention label stand in for an action.

Objects or places + availability + bodily consequences

Use: remember that a particular support helps several later movements.

Failure: a visible object gets credit merely because it often appears near successful attempts.

Design: connect named-entity associations to the actions and transitions they enable. Test removal or substitution, including an unrelated object as a comparison.

Sensor quality + bodily readings + prediction confidence

Use: recognize when a quiet signal reflects lost sensitivity rather than recovery.

Failure: a damaged or masked sensor reports less pressure, which is mistaken for greater wellness.

Design: preserve valid/missing flags and available measures of sensing capacity. Do not give the acting model hidden clean readings that the body cannot sense.

Old success + current body + changed surroundings

Use: reuse an experience while adjusting for a different load, grip or movement capacity.

Failure: replaying an old sequence assumes that the body, world and learned encoding are unchanged.

Design: retrieve by current context, forecast again, and revise commands from new observations. Version stored encodings or keep enough source data to refresh them.

3. Extend one connected system, rather than attach a new score-seeking controller.

Attention computes which stored information contributes to the current prediction. It needs a useful learning target. Simply adding attention to a wellness derivative does not specify what it should learn.

  1. Record aligned transitions. Each record links the observation before a command, the command actually applied, its start and duration, the next observations, and measured bodily channels. Include command identity, episode identity and validity flags. Preserve current intentions as context, not as proof of success.
  2. Keep detailed recent history and linked longer history. Retain enough consecutive records to resolve short transients. Build time-aware summaries for longer intervals, with links to retained episodes. Include ordinary stable periods and failures, not only dramatic changes. Limit storage explicitly; full videos are not required for every record.
  3. Retrieve relevant past episodes. The query uses information available now: bodily condition, scene, recent commands and the outcome being considered. The retrieved records may contain the outcomes of completed past episodes. They may not contain future observations from the current episode.
  4. Predict several futures from the same history. Condition on each possible command sequence and predict future observations and bodily channels at short and longer delays. Teach both sudden events and sustained effects from their later measured outcomes. Use the existing forward model, memory and bodily forecast routes as the starting point.
  5. Let the forecasts affect goal choice and planning. Memories provide possible outcomes and useful starting sequences. Compare their predicted bodily consequences from the current state, then refine the commands. Execute a short portion and update from real readings while continuing to consider the longer consequence.

Rapid correction and long learning serve different jobs. A new observation can immediately change the next prediction and planned command using existing weights. A new episode can become retrievable before extensive retraining. Later training improves what generalizes to other situations. Actual correction latency needs measurement; adding a memory does not establish that the loop is fast enough.

The current execution clocks also matter. In the preserved branch, limb commands are held for five model steps, while intention runs every ten. The training loop continues sensing and learning between those changes; gaze is not held with the limbs. These are separate from the recording interval and the length of an imagined future. Convert them to seconds using the recorded simulation timing, not an assumed half-second for every step.

Technical contract: what is learned?

Let H_t be the time-stamped history available at decision time t. Let A be the candidate future command sequence. Let b(t) contain separately named, measured bodily quantities. The forecast returns a distribution over later observations and bodily quantities, conditioned on H_t, retrieved past episodes and A.

Inputs: available history + retrieved past episodes + candidate commands + elapsed times
Outputs: predicted observations, bodily channel trajectories, and uncertainty
Teaching targets: later measured observations and bodily channels from executed sequences
Derived changes: [predicted b(t+h) - measured b(t)] / h

Train measured outcomes with validity masks and an appropriate prediction loss, including a probabilistic loss where uncertainty is predicted. Later observations are targets, not earlier inputs. For rollout learning, distinguish teacher-forced inputs from imagined inputs and evaluate both. Grounded targets must not move to match predictions merely to reduce error.

For short events, include the interval peak, its time and event order where the sensor records them. For longer effects, predict duration and cumulative exposure as well as endpoint state. A compact summary must be tested for the information it loses. Missing follow-up or an episode ending is an unknown outcome, not a successful recovery.

Do not create one new independent model per timescale by default. Start with shared time-aware memory and consequence prediction, adding explicit horizon-dependent outputs only where they answer a missing question. Check compatibility with existing self forecasts and latent-body before adding overlapping heads. Preserve all learned state through explicit migration if dimensions change.

For effects longer than the existing windows: carry forward time-stamped summaries of body state, commands, contact and exposure; keep links to the earlier episode records; attach the later observed consequence when it arrives. Teach a forecast conditioned on the requested elapsed time, or a sequence forecast over those summaries. Do not simulate every millisecond of an hour as a first design. Keep the detailed recent path for fast corrections and use slower learned transitions for long consequences. A restart must preserve pending earlier-to-later associations, while an actual episode reset must not invent physical continuity.

For rare events: retain important transient windows alongside representative ordinary experience. Record how samples were selected. Repeatedly replaying a fall is useful for learning its mechanics, but replay frequency must not be mistaken for its real probability. Check likelihood estimates on representative held-out episodes. Split validation by episode and changed conditions, not overlapping windows from the same experience.

4. How should this change the goals the planner chooses?

Choosing a desirable remembered snapshot first can miss the cost of reaching it. The same end position can be reached through a stable movement or through an injury followed by recovery.

Recommendation: compare attainable outcomes together with the predicted paths to them. Include keeping the current command as an option, but predict its actual physical effects: an unchanged command does not freeze a falling body. A remembered outcome supplies a candidate; its current predicted consequences determine whether it remains useful.

Memory alone will not fix a planner that cannot consider the needed path. In the inspected _plan_chain, valid physical goals and non-world hand-target modes limit the chain to one command. Another check stops further expansion after at least two commands if distance rises more than 5% above the best earlier distance. A preparatory body shift can temporarily increase that distance. The check was introduced to contain diverging predictions, so simply removing it is not the solution. Separate prediction failure from a physically useful detour, propagate predicted body state through the sequence, and test that the whole-path comparison admits the useful movement without accepting exploding forecasts.

Do not optimize the wellness derivative alone. If wellness starts and ends at the same value, its signed changes sum to zero regardless of how painful the middle was. Counting only positive changes is worse: it can favor becoming unwell and then recovering. Stable wellness must remain valuable.

Keep channels separate until their meaning is evaluated. A tactile-comfort reading, a loss of sensing capacity and prediction error are not interchangeable units. Use UEMA's grounded wellness definitions and explicitly trace which consequences each planner forecast contains. Channel meanings and tradeoffs cannot be supplied by attention alone.

A whole-path comparison should account for bodily condition throughout the movement, brief severe events, and what is likely to follow its endpoint. A learned forecast of later bodily condition can supply that continuation. A three-second horizon must not make an impact just after three seconds disappear.

Important design distinction: learning to predict bodily consequences and using them to search for commands preserves the proposed prediction/intention route. Training command-network weights directly to maximize those consequences is a different objective. Calling a signal intrinsic does not settle the difference. Some mathematical overlap with model-based reinforcement learning is possible; the computation and learning targets, not the label, determine the architecture.

The tradeoff that must remain visible

Any final choice among conflicting consequences uses a preference, whether it is a grounded wellness formula, a learned self evaluation or a fixed ordering. This proposal does not hide a new set of hand-written tradeoffs inside an attention block. Retain the current grounded definitions initially, map their forecast coverage, and compare candidate rankings on the cases below before changing the definitions.

Expected average wellness alone can underrepresent rare severe harm. Preserve predicted severity, probability and duration so a severe outcome is not averaged away before self evaluation. Multiple samples of one model can share the same mistake; agreement alone is not calibrated confidence. The precise treatment belongs in the wellness design and must be tested explicitly.

Likewise, an arbitrary ball does not become a useful goal merely because a sequence memory exists. Its relation to control, exploration or another existing intrinsic drive must reach goal selection. Audit those existing connections rather than adding a task-point reward for this example. A goal chooser should learn from the system's actual intrinsic consequences, not from the example writer's preference for a grasp.

5. Which comparisons would decide whether the design works?

These are proposed comparisons for operational resumption. They are grouped so one preserved-state experiment can answer several questions. This review has not launched model tests.

QuestionComparisonResult that matters
Does it assign the catch the right role?From the same unstable state, compare catching and not catching. Separately compare preventing the loss of balance from an earlier state.Forecast and actual outcomes distinguish prevention, helpful recovery and avoidable harm. The catch is not blamed merely because pressure follows it.
Does it preserve a brief sequence?Use the same short events in different orders, including several events within one half-second interval. Does it recognize delayed benefit and harm?Compare paths with similar early readings but different later outcomes, including an effect beyond the short planning horizon.Goal and path rankings reflect the later consequence once supported by experience, not just the immediate derivative.
Can it preserve wellness without creating trouble?Stable condition versus disruption followed by relief, with the same final condition.The disruption is not attractive merely because recovery creates a positive change. Preventive action can be valued without an observed improvement.
Is history useful rather than decorative?Compare intact history, time-shuffled history, state-only prediction and an equal-compute recurrent summary without retrieval attention.History improves held-out temporal predictions or choices where the current observation alone is ambiguous. Extra attention is retained only if it adds useful performance.
Can it avoid misleading information?Alter later observations while holding earlier available inputs fixed; mask a sensor; change an irrelevant object; end a recording before recovery.No future leakage, no lost-sensation-as-recovery inference, no spurious object credit, and no invented outcome after recording ends.
Does long memory remain useful?Resume preserved learning, change load or body capacity, and compare retrieval with no retrieval at matched conditions.Relevant old experience helps while changed conditions alter the forecast. No blind replay, state reset or dependence on obsolete encodings.

Order of implementation decisions: first settle recording and alignment; then show temporal prediction benefit; then show the predictions change the intended goal and commands correctly; finally measure retained physical ability. A better prediction loss alone does not establish a better grasp or recovery.

6. What the code and research actually support

Current code: the parts already present
  • PersistentMemory has a GRU, meaning a network that carries a learned summary through time; query/key attention; a readout into model processing; and a five-output bodily-needs predictor. Its history uses simulation timestamps and rejects future or unordered events.
  • MemoryHistory defaults to 128 retained samples at half-second intervals, plus a compressed earlier prefix. Each interval selects its largest observed feature change. A short event is eligible, but only one selected event survives each committed interval. The documented feature-change weighting is affected by feature count and numerical scale. It is not a declared importance measure for wellness.
  • LemLite trains a memory-conditioned bodily forecast against measured needs. The stored branch has persistent memory on and its centred repair selected. This is saved-state evidence, not a report that a process is running.
  • Self-state integration already teaches executed command sequences at horizons of 1, 5 and 20 model steps, plus 100 on a sampled schedule. It supplies actual command durations and every intervening target. This is a foundation to extend, not missing sequence learning to invent.
  • SelfRehearsal retains full windows across episodes, split between uniformly sampled experience and windows selected for change. Its change score uses only the difference between the first and last bodily targets. A large middle transient followed by recovery can score zero in the change-selected bank. The uniform bank can still retain it. Preserve that bank and evaluate peak, duration and sequence-aware retention for the other bank.
  • The existing forecasts have different meanings: persistent memory predicts pain, pleasant contact, capacity, pressure and shear; self dynamics predict local sensing/function fields and capacity; the approximate wellness evaluator predicts a different five-term set. Equal output counts do not make these the same signal. Map their producers, validity and consumers before combining them.
  • The goal ring still ranks remembered moments and selects target representations, with conditional revaluation and locality paths. This differs from comparing complete predicted paths to competing outcomes.
  • The approximate wellness evaluator predicts five named terms. The source documents that other grounded terms are outside that evaluator. This coverage must be reconciled with the different five-needs memory forecast and the separate self-state forecast.
  • IntentionGenerator already contains command search, optional predicted-wellness scoring and sequence-related code. A class for attention across imagined rollouts also exists. Existence of a class does not identify the active route in a preserved run.
  • In the preserved branch, self_state=learn, self_choice=off and prospective_wellness=off. Learned bodily forecasting therefore must not be described as an enabled direct self-choice route. Persistent memory can affect ordinary model processing through its own readout. A newer worktree contains additional imagined-memory and outcome-value work; reconcile that work before duplicating it or describing it as adopted here.

Exact source hashes, saved-branch settings and independent review are retained in the review record. The specification supplies the intended roles; dated implementation notes are reconciled against code.

Useful research, with its limits stated precisely

Keramati and Gutkin's homeostatic-learning model relates learned choices to internal physiological state and anticipated future needs. It supports examining state-dependent value and prevention. Its reinforcement-learning construction is not automatically the implementation UEMA should adopt.

Jain and Wallace demonstrate cases where attention weights do not explain a prediction. Wiegreffe and Pinter show why attention's explanatory value requires a careful test rather than a blanket dismissal. Both concern language models. The useful design lesson here is to test causal influence and prediction benefit instead of treating a bright attention weight as proof that a command caused an outcome.

Research on dopamine-dependent credit assignment examines how reinforcement relates to preceding behavior and action sequences. It motivates taking time and preceding activity seriously. It does not establish that a particular UEMA attention block, half-second interval or long-term memory is biologically equivalent.
