Move the body.

MIMo is the simulated child-shaped body shown on this page. MuJoCo is the software that calculates its motion and contact with things. UEMA is the learning model meant to choose its movements. The goal is for experience to teach UEMA how to move closer to an object, reach it, and grasp it.

The full solution must connect a useful goal to timed movements of the whole body. Looking, leaning, reaching and opening the fingers can happen together. Each new result must be available to update the prediction and the next choice.

What this page gives you: a specified proposed movement loop, a worked example in six half-second (500 ms) movement moments, including the algorithms, data fields and learning targets for its missing connections. The original reports are unchanged. Implementation and training remain stopped under your instruction; this document and its illustrations are the newly authorized work.

1 · The parts of UEMA, and where each step of the solution acts

Read the blue arrows as “passes information to.” A command is a set of requested movements. A prediction is the model’s estimate of what those movements will cause. An interval is a short part of a movement with a start and end time. Uncertainty means how far a forecast might be wrong. The same numbered parts appear in the sequence diagram below.

Two inputs to each forecast: the planner passes the current situation and a timed movement plan to the forward model. The value comparison also reads the intended outcome, so it can compare futures for that same goal.

1

Senses and encoders

Eye images, joint angles and touch enter encoders. The encoders produce numeric vectors for the core. Added patch matching associates the same object across eye images and time.

Output: sensory vectors, object position estimates and error ranges.

2

Transformer core and memory

Current sensory vectors and earlier context enter the core. Attention combines those vectors; memory retains earlier observations and real command windows.

Output: current context and recorded start/command/end windows for retrieval.

3

Intention

Retrieve observed outcomes from similar starting situations. Compare their estimated future benefit from the current state. Retain one object-and-body relationship, separate from the movement table.

Output: object track, desired relationship ranges and required hold duration.

4

Planner

Build 16 timed command tables from retained, retrieved, current and hold seeds. Change executed control amounts and start times. Keep four best predictions and sample a second round.

Output: the first 50 ms row of the best table allowed by the harm, validity and uncertainty checks.

5

Forward model and imagination

Starting state plus one command row enter the forward model. Its outputs predict joint, eye, object and touch changes. Feed that changed state into the next row, with a private copy of memory.

Output: a three-second predicted state sequence, with applicable measured error bounds or an explicit unqualified flag.

6

Wellness and later value

Read predicted channel values at every interval. Sum their time-weighted benefit and cost, then add the learned continuation estimate for the final state and intention.

Output: one score per sequence that passes the checks, with the same weights and time scale.

7

Motor control

Read the chosen body, eye and finger requests. Apply the production limits and filters once. Pass the resulting controls to the physics program.

Output: actual controls and their start/end times for matching to observations.

8

MIMo body and MuJoCo world

Joint forces act while contacts resist motion. Images, joint sensors and skin sensors record the resulting body, object and pressure changes.

Output: observed results for the next choice and matched prediction/value lessons.

Where the learning happens: compare a forecast with what actually followed the command. Use that experience to improve the forward model, the useful-outcome estimate and future movement proposals. Keep the experience across later attempts and restarts.

2 · From an observed ball to a timed movement choice

The eight lanes below are the same eight parts as the map. A state record contains current body angles and speeds, object tracks, touch, core context and control history. A command table contains simultaneous body, gaze and individual finger requests, one row per 50 ms. Ten rows make each 500 ms illustrated moment. An intention names the tracked object and a desired body–object relationship, such as sustained hand control observed in earlier experience.

The top half specifies how the proposed system constructs and compares those tables. The lower half shows the joint changes needed in this particular illustrated example. Those lower labels describe the posed movement; they are not a six-stage routine to install in UEMA.

Diagram key: q means joint angles. FK calculates connected bone positions from those angles. body[26,9] means 26 body targets with nine fields each: position, rotation, radius and strength. gaze[2] means the two eye-direction angles. joint_goal[J] holds named joint targets, including each finger joint; J is the number in the saved joint list. A mask says which requests are present. dt is the row's duration. Utility means the combined bodily benefit and cost; a continuation is the estimated benefit over the next three seconds.

Read top to bottom. On a narrow screen, scroll the diagram sideways. Open the full diagram · Mermaid source.

What replaces “try different commands”: two rounds of 16 tables; perturb permitted movement coordinates, shift separate body/eye/finger boundaries by up to two 50 ms rows, forecast each row, keep four best, and execute only the best first row. The full field definitions and failure rules are in section 5. The sampling sizes are proposed settings, not measured performance. The initial design retains one goal relationship for a six-second evaluation period, checks it every 500 ms, and replans commands every 50 ms. Achieving the relationship starts maintenance; harm or lost object identity switches to protection, whose measured costs remain in this attempt. These are different clocks, not six-second movement commands.

How realistic is this clock?

You requested 500 ms per moment, so the illustration uses six such moments. For a human reference, one study reported average hand-transport times of 667–695 ms across three target positions in healthy older adults. That study did not include this MIMo body shift. It supports showing overlapping reach and finger closure on a subsecond scale; it does not establish this three-second example as MIMo’s measured speed. Study and measured times.

The real controller needs shorter opportunities to react to contact and slip. Movement time means time inside the simulated world. The time the computer takes to calculate or train is a different measurement. A later physical recording must report both, using its recorded clock.

5 · Exactly how the proposed solution works

The repair has to do three things together: keep track of the same object, compare different whole-body movements, and learn from what those movements actually cause. The following is a proposed implementation specification. It chooses the missing algorithms. It does not describe code already running. Model changes and training remain stopped.

Each box below gives the readings that enter, the calculation, the result and the next user of that result. The ordinary text explains the mechanism. The expandable text fixes its data fields, equations and starting settings so that an implementer cannot replace them with “use learned proposals.”

A · Keep the ball separate from the hand and the background

Input: the two eye images, measured eye and head angles, joint angles and recent touch readings. Calculation: match small image patches between eyes and between successive images. Two eyes view the same surface from different places; that difference gives an estimate of its distance. Group neighboring patches with similar depth and appearance. Match each group to its earlier group after estimating camera motion from background patches and measured head angles. Output: a numbered object track containing its estimated position, motion and error range. The number follows the observed object; it is not MuJoCo’s hidden object name.

This solves a specific problem: when the body leans, the ball moves in the eye image even if it stays still on the stand. Subtracting the camera’s motion prevents that image change from being counted as movement of the ball. If the hand hides the ball, retain the last track, advance its position using its predicted motion, and enlarge its error range. Do not silently replace it with a nearby object.

For touch, associate a finger’s measured contact with a tracked surface only when their estimated positions agree within their combined error ranges. Otherwise keep the contact’s object identity unknown. The forward model receives both the track and that uncertainty.

Exact proposed perception and state record

The current vision encoder has eye/patch information, but the reviewed goal ring stores whole sensory snapshots. This explicit object association is an addition. It uses image correspondence and known camera geometry, not scene object coordinates or a hard-coded red-ball detector.

  1. Use the existing eye-tagged image patches before global pooling. For each patch, retain its image coordinates and normalized feature vector. Match a patch to the minimum feature-distance patch along the other eye’s epipolar line, the line where the same surface can appear. Reject matches whose best distance is not separated from the second-best distance by the held-out matching-error bound. Triangulate accepted pairs using camera calibration and sensed eye/head pose.
  2. Join adjacent accepted patches when their depth and appearance differences are within three estimated standard deviations of sensor/matching noise. A standard deviation measures the spread of those errors. Keep unmatched patches as unknown depth. Split a joined region when its patches move differently over time. Exclude the known body surface by projecting its FK geometry into the eye images; keep the exclusion uncertainty at boundaries.
  3. Match old regions to new regions by minimum total assignment cost: squared position error divided by position variance, plus squared descriptor error divided by descriptor variance. Reject a pair above the 99th-percentile cost of correct matches in a held-out sensory sequence. On an ambiguous match, retain competing identities; no grasp-completion claim is allowed until the identity is resolved. Keep up to eight tracks in this initial design; retain the intention’s track and nearest contact tracks before lower-priority tracks.
  4. For each track store {id, image_mask, appearance_vector, position_xyz_m, velocity_xyz_m_per_s, shape_points_m, covariance, visible, last_seen_time}. Positions use one declared body-relative frame. Transform earlier positions into the new frame before estimating velocity. A constant-velocity prediction and Kalman measurement update supply the initial track estimate. Learn the action-dependent motion correction from later observed track positions; do not label an occluded prediction as an observation.
  5. Estimate camera motion from stereo patches on the background, excluding the body and separately moving object regions. Fit the six-parameter rigid change between consecutive three-dimensional patch sets with RANSAC: repeatedly fit from a small subset, count matches within the calibrated depth-error bound, and retain the fit with the most agreeing matches. Require at least 20 matches spread across three image quadrants and more than half of the eligible matches to agree. These are proposed settings. Convert camera motion to body-root motion using the measured head/eye joint geometry; use vestibular gravity to check tilt. Joint angles alone do not measure root translation. Store root pose in an estimated local frame anchored at the first image, with covariance and validity. This is visual odometry, meaning motion estimated from successive images. A mostly moving background, poor texture, or failed agreement makes root/object motion uncertain; withhold object-control credit and object-directed action outside the qualified uncertainty range. Simulator world coordinates are for evaluation only, never acting inputs.
  6. The full current-state record is S = {all sensory tokens and validity, core context, memory, joint angles q, joint velocities qdot, estimated local root pose/velocity and covariance, eye angles, object tracks, skin contact history, previous dispatched controls, filter state, time, episode_id, schema_version}. A token is an encoder’s vector of numbers for a sense. Body angles and velocities come from proprioception; estimates and observations carry different flags. A missing required field makes the corresponding forecast unqualified, not zero.

Failure that changes the design: object identity swaps during a camera turn, or depth error is large enough to confuse contact with a visible gap. The immediate correction is to fix matching/calibration or widen the stated uncertainty before those tracks can guide grasp choice. A whole-scene token alone does not satisfy this interface.

B · Get possible goals from actual experience, then keep one

Input: saved movement windows, the current object tracks and the body’s current needs. A movement window contains what was sensed before, the commands sent, and what was sensed afterwards. Calculation: retrieve windows whose starting body and object relationships resemble the present ones. Their observed endings supply possible outcomes. Recalculate the likely benefit of each outcome from the current situation. Output: one stored intention: the object track, the desired relationship to the body, and how long that relationship should last.

For example, an earlier experience may show that finger contact allowed an object to move with the hand. The reusable goal is that relationship with the currently tracked object. It is not the earlier camera image or the earlier joint angles. The movement search must still find how to produce that relationship from here.

If no such experience exists yet, there is no pretend “learned grasp proposal.” Limited exploratory movements create the first contact and motion windows. Their observed endings become retrievable examples. No instruction saying “lean, then reach, then curl” is added to the acting model.

Outcome representation, retrieval and intention lifetime

For every real window of 0.5, 1, 2 and 3 seconds, store its start-state reference, actual command sequence and an outcome descriptor. The descriptor contains object-to-palm position and velocity, which digit surfaces contacted that object, pressure/shear ranges, body support readings, and the duration each relationship persisted. Save raw sensory references so these descriptors can be rebuilt if the perception code changes. A descriptor with unknown identity or missing touch remains partial.

Retrieve 32 windows by smallest normalized start-state distance, using joint angles/velocities, object-to-hand positions, object size, support contacts and needs. Divide each numeric difference by its recorded sensory error scale before squaring; compare only fields valid in both records and require object/hand/support fields. Keep diverse endings by selecting the best member of each distinct descriptor cluster. The initial shortlist is four outcomes, including continuation of the current intention. These counts are proposed search settings, not measured capacity.

Rebind an outcome to a current object only if its size/contact geometry fits within the recorded uncertainty and observed joint range. The intention stores {track_id, desired_relationship_ranges, required_valid_fields, required_hold_seconds, source_window_ids, created_time, last_progress_time, evaluation_end_time, achieved}. The minimum proposed hold is 0.5 s, or the source window’s longer observed hold. Completion requires every required relationship to remain in range for that continuous duration in actual readings. A single touch cannot complete it.

Rank these four outcomes by unshaped predicted bodily/control utility from the same current state, using the search in D for each outcome. Use the qualified later-value estimate when available; during cold start use only the three-second predicted utility. Never compare different goals by their goal-distance bonus. An outcome cannot outrank the current intention unless its estimated advantage exceeds twice the relevant held-out value-error bound. For the initial qualification design, retain the selected relationship for a six-second evaluation period. Check its validity and progress every 0.5 s and immediately on harm. Reaching the required hold marks it achieved; continue comparing movements that maintain that same relationship until the evaluation period ends. This is a generic relationship-maintenance choice, not a fixed hand pose or a named grasp routine. Ordinary goal replacement occurs at the end of that period. After 2 s without progress, widen the allowed search variations within the existing physical envelope; do not fabricate a new successful-goal label. Six seconds is an explicit design setting, not an infant timing claim. If identity becomes ambiguous, suspend object-directed closure, mark this intention period failed, and use the existing protective path for the rest of its period. Retain g and a failure flag in its record so later measured costs are still attributed to this attempt. A new attempt to reacquire the object starts a new period, not a silently repaired old identity. A restart retains the intention and its elapsed duration.

Why any grasp would be worth selecting: usefulness must come from bodily benefit, measured control of the environment or useful learning. Object presence beside a comfortable body is insufficient. If none of those signals values object control, connecting a planner will not make grasping desirable. The proposed control measurement in F supplies the missing causal distinction without a “ball grasped” reward.

C · Write every alternative as a timed table of commands

Input: the current command, retrieved real command windows and the unfinished part of the previous plan. Calculation: put each alternative on the same clock. Each row contains body requests, eye requests and individual finger-joint requests. Output: a command table the predictor and the real command path can both read.

One row lasts 50 ms. Ten rows make one of your 500 ms movement moments. A row can turn the torso, open the elbow, change gaze and bend one finger together. To delay a finger change by 100 ms, move that finger change two rows later without moving the body or eye columns. This is what changing the timing means.

The exact fields, units and authority

For one body, each row is A[k] = {body[26,9], requested_gaze[2], joint_goal[J], handle_mask[26], dt=0.05}. Each body row contains target position xyz in dispatch centimetres, orientation quaternion wxyz, radius and strength. Only fields actually consumed by the bound production decoder may vary. Radius or position fields ignored by that decoder remain fixed. Eye azimuth/elevation and explicit joint targets use radians; absent targets have an explicit absent flag. J is read from the bound joint registry, with names and limits saved beside the table.

There is one dispatch owner. The selected body rows go through the existing planned-execution filter. Explicit hand-joint targets have the same priority and smoothing as the production finger-target path. Requested gaze is passed separately through the production gaze path; its body eye-row representation is derived from that request. The search cannot independently optimize two contradictory eye instructions. The predictor copies the same filter state and decoder configuration once per alternative. It applies each filter once per row.

Before dispatch, write {body_id, episode_id, order_id, start_sim_time, requested_row, filter_state, predicted_end}. Afterwards attach the actually sent controls and measured endpoint. The future realized gaze or an after-the-fact motor ledger cannot be an input to the prediction made before movement. The existing NativeInputV1 already distinguishes those quantities.

D · Generate alternatives by changing numbers, then keep the better ones

Input: the timed tables from C. Calculation: make copies with different allowed movement amounts and start times. Predict and score each copy. Keep the four best copies, then make a second set around them. Output: the highest-scoring allowed table. Only its first 50 ms row is sent to the body.

This permits support-before-reach without naming it as a routine. One copy may extend the arm immediately. Another may change the trunk and supporting arm first, while postponing the same right-arm extension. The forecast must carry the resulting shoulder movement into the later reach. If the second copy can reach and retain the object with acceptable bodily costs, its full-sequence score can exceed the first.

Chosen initial search algorithm: two rounds of sample-and-refit
  1. Use a three-second table: 60 rows at 50 ms. Compress it into six 500 ms control blocks for sampling, then expand it back to rows. The body groups are trunk/head, left arm, right arm, left leg and right leg; gaze and each of the ten digits are separate groups. Bind each group to named handles/joints in the saved registry, with no overlapping command ownership. Each group has its own block boundaries. Start from four seeds: the previous plan shifted by one row, a retrieved real window, the current controller’s proposal, and a current-position hold request. A hold request is not assumed to be physically safe.
  2. Create 16 alternatives in total per round, retaining the unmodified seeds. For the others, choose one, two or all body groups with equal probability; independently include gaze and individual digits. Perturb normalized executed position/strength/joint coordinates by zero-mean Gaussian noise with initial standard deviation 0.05 of their permitted range. Perturb orientation in three-axis rotation coordinates, then convert to a unit quaternion. Do not add arbitrary noise to quaternion components.
  3. For every selected group, shift a boundary by one of −2, −1, 0, +1 or +2 rows, uniformly. Clamp blocks to at least one row, keep boundaries ordered and retain the 60-row horizon. Independent boundaries allow fingers, eyes and trunk to change at different times. Interpolate requests between knots, then apply joint, speed and decoder limits. Reject nonfinite or contradictory fields before prediction.
  4. Predict all 60 rows, using E. Apply F’s score and admissibility rules. Retain the four best admissible alternatives. Refit each sampled coordinate’s mean and variance to those four; keep a standard-deviation floor of 0.01 of its allowed range so it does not collapse to identical commands. Generate the second set of 16 around these retained tables, again retaining the best unchanged.
  5. Stop after two rounds. Select the best admissible table across both rounds. On an exact score tie retain the previous plan; otherwise use stable candidate order. If none is admissible, do not dispatch the apparent best unsafe table: follow G’s acquisition/protection rule. After an actual 50 ms interval, shift the table and repeat from the new readings.

The initial cost is at most 1,920 one-row forecasts for one retained intention, batched where possible: 16 alternatives × 2 rounds × 60 rows. Comparing all four outcomes costs at most 7,680 forecasts; do that when choosing a new six-second intention period after the previous period ends. During a period the 0.5 s checks keep the same relationship or enter its failed protective branch on harm/identity loss; they do not replace g or erase its later measured costs. This is a compute count, not a claim that the current computer finishes it in 50 ms. In a simulator the world must wait for a valid next command if necessary. Measure wall-clock cost before choosing a production search width. Reducing width must preserve the whole-body/timing alternatives in the comparison; it must not silently turn the search back into repeated single commands.

The 16/4/two-round settings and noise sizes are explicit starting design choices. Their useful result must be measured against the same-state current planner. Retrieval supplies experience-based proposals in this first design; there is no unspecified additional proposal network. Storing each real window adds another possible seed, including failed windows that expose a bad forecast.

E · Predict the changed body, contact and object before predicting the next row

Input: one starting-state record and one proposed command row. Calculation: the existing forward model combines the sensed situation with the requested movement. Added outputs predict joint changes, object movement and touch over the interval. Output: the next state, including the new shoulder position, object estimate and pressure. That output becomes the next row’s input.

The predicted elbow cannot float away from the upper arm: predicted joint angles are converted to connected body geometry using forward kinematics, or FK. FK computes positions from the actual bone lengths and joint angles. It does not supply balance or grip force. Those come from the predicted motion and touch, learned against actual physical results.

Prediction heads, targets and recurrent state

Reuse the current core and its learned motor/body prior. Preserve their saved weights. Add versioned prediction outputs where the native path lacks a required quantity. The existing body prior predicts handle positions and rotations, not joint angles. Its outputs therefore cannot be directly added to joint-angle predictions as a residual correction. The new joint head predicts observed joint changes in its own units, using the old prior as an input feature. Pretrain that head on preserved, matched actual joint readings before allowing it to guide movement; freezing the old prior preserves its weights, not the new head's accuracy. The existing controller remains the reference until the new head passes the same-state physical comparison. The proposed joint/motion head reads the core output, starting q/qdot, requested controls and old body-prior output; two 256-unit GELU layers produce joint-angle/velocity changes and root translation/rotation/velocity changes. A track head with shared weights per object reads its descriptor, body-relative position/velocity, contact associations and the same core/control input; it predicts position/velocity changes and uncertainty. A skin-site head reads the starting site features, body/track context and control and predicts five 10 ms pressure/shear/contact samples per 50 ms row. These are chosen new interfaces, not existing qualified outputs.

Teach joint changes and valid estimated root changes with the matching before/after difference; use squared error divided by a frozen per-field sensory-error scale. Root rotation uses a three-number shortest rotation, not subtraction of quaternion components. Teach object position/velocity only on valid associated observations, using Gaussian negative log likelihood with a positive variance floor. Teach contact presence with binary cross entropy and pressure/shear with squared error in log(1 + magnitude/scale) units, using the production sensor’s scale. Save the actual five-substep history; endpoint pressure cannot be substituted for it. Teach each existing sense-token output against its matched next observation in its own existing normalization.

For a candidate’s next row, update q/qdot and root state, recompute all body/skin positions by FK, update object tracks and contact features, append predicted sensory tokens to that candidate’s context, and advance its private memory. Copy the evolving control-filter state too. No candidate writes into lived memory. Do not carry the original touch, object position or shoulder into every future row. Train short multi-row rollouts against contiguous real windows as well as one-row targets so accumulating errors become visible.

Joint limits constrain geometry. Reject a predicted joint-limit or body/object collision violation outside the permitted contact tolerance. A learned pressure/force forecast can still be wrong even when FK geometry is valid; compare its saved pre-movement forecast with later measured contact. The proposed IK use is limited to fitting a requested body configuration into legal joint angles where the existing decoder requires that conversion. IK must not quietly supply the whole reach-and-grasp sequence.

F · Count later usefulness as well as the cost of getting there

Input: each predicted sequence, the same stored intention and the current bodily priorities. Calculation: add the useful and harmful effects over the whole three seconds, then add a learned estimate for the next three seconds. This initial design compares six seconds in total when that later estimate is qualified. Output: one comparable score per admissible sequence. A support shift can win even if its first 500 ms does not reduce hand-to-ball distance.

The estimate of later benefit reads the object relationship and intention as well as the body’s condition. This is a specific change from the current diagnostic estimate, whose input is five bodily readings and their recent averages. Comfortable but out-of-reach and comfortable with the object in hand must be different inputs.

Exact score, usefulness signal and delayed learning target

Define a new, explicit exploitation scoring contract: retain the active production channel names, signs and weights except set the planning weight of learning progress to zero. Use actual measured learning progress to allocate exploratory command coverage instead. This separates useful execution from the chance to learn; it does not claim to preserve the production weight vector unchanged. The source list includes integrity, controllability, learning progress, coherence, contact control, consequence, self value, agency, prediction error, tactile comfort, capability, movement, curiosity and efficiency. Pain/harm retain their separate protection role. Do not replace that full list with the diagnostic five-channel input, and do not assume efficiency has a nonzero weight. The source default weights are integrity 2, controllability 1, learning progress 0.75, coherence/contact control/consequence/self value 0.5 each, agency/prediction error/tactile comfort/capability/movement/curiosity 0.25 each and efficiency 0. In this proposed exploitation contract learning progress becomes 0. Copy any actual run overrides explicitly. Pin one raw-channel centre/scale/floor snapshot for an entire value-model and data version. Unlike the goal ring, these raw utility inputs are not detrended separately on insertion. Changing the weights or normalization starts a new scoring/value version; it cannot reuse targets as if their units were unchanged.

Let x[k,c] be the predicted raw value of channel c during row k, and N_c the pinned raw-channel normalization (x - centre)/max(scale,floor). Let w[c] be the pinned weight, dt=0.05 s, t[k]=k×dt, and gamma(t)=exp(−t/20 s). Twenty seconds is the existing declared discount assumption, not a measured infant constant. Let V_c(S,g,h) predict accumulated channel c over exactly h more seconds from state S under intention g. At the start of an intention period, the total comparison horizon is six seconds: three seconds explicitly forecast and a three-second learned continuation. Later choices clip the horizon to the time remaining in that same period. Set explicit duration L=min(3 s, remaining time) and continuation H=remaining time-L. Use the equation below with 3 s replaced by L, state 60 replaced by the last explicit row, and value duration 3 s replaced by H. When H is zero there is no continuation term. Six seconds is a proposed finite horizon, not a claim that every useful task fits within it. Longer delays require a separately qualified longer-horizon design. Use:

utility(A | S,g) = sum_k gamma(t[k]) * dt * sum_c w[c] N_c(x[k,c])
                   + gamma(3 s) * sum_c w[c] V_c(S[60],g,3 s)
score(A | S,g) = utility(A | S,g)
              + sum_k gamma(t[k]) * [gamma(dt)*phi(S[k+1],g)-phi(S[k],g)]
              + gamma(3 s) * V_phi(S[60],g,3 s)

Make the intention affect the command now. For each required relationship in g, calculate the distance from its desired interval, zero when inside it. Divide by its frozen sensory tolerance, square, and average. Call that number D(S,g). Set phi(S,g)=-D(S,g); the coefficient 1 is an explicit proposed scoring choice. Each row adds gamma(dt)*phi(next,g) - phi(current,g), discounted by the row's starting time. This favors progress toward a retrieved outcome during a short search without a named grasp rule. Missing identity or required fields invalidate ordinary object-directed scoring. On a failed attempt, preserve the last valid unmet-goal distance as evidence and define each subsequent potential increment to be zero, including the transition into failure. Do not set phi to zero and accidentally award the same progress as satisfying the goal. The failure flag selects this branch explicitly; the valid-state telescoping formula applies only while the relationship is observable.

The value model also learns the accumulated potential increments as a separate output, with the same observed-return target. At the planned evaluation boundary the remaining horizon is zero. Do not insert an artificial final potential jump; use the last actual relationship for the final valid increment. Failure follows the separate zero-increment rule above. Goal changes close the old goal window; never calculate one increment between two different goals. Over this finite horizon, the increments telescope to the discounted final potential minus the fixed starting potential. They can therefore prefer finishing nearer the retained outcome. They are a declared goal-directed heuristic, not observed bodily benefit. A failed branch stops adding potential increments; it is not treated as satisfaction. Predicted harm, lost identity or mandatory missing observations disqualify a planned object-directed sequence before scoring, so a favorable utility total cannot authorize a predicted abort. Goal selection and replacement use unshaped utility; otherwise a farther-away goal could win simply because it starts with a larger distance.

Where every forecast channel comes from. The current native module already has a raw-channel readout and channel_lesson: detached interval response features enter a Linear → GELU → Linear network; its outputs are taught by the matching actual raw _wellness_channel_vector values, before detrending. Extend that input with a candidate-local history record: previous raw channel values, contact/control gates, agency/consequence counts, curiosity state and the named running averages used by those producers. A companion head predicts the next history values, taught against their actual next snapshots. Carry that predicted history to the next row. Derive integrity/harm from predicted pain and motor-state using the existing formula; predict the missing motor-state quantity from matched actual motor-state readings.

The exploitation score does not predict future learning progress or update model weights inside imagination. Actual held-out learning progress is read by the acquisition allocator, which gives half its bounded exploratory slots uniformly across enabled body groups and half in proportion to positive recent progress, with uniform allocation if all progress is zero. Each digit and gaze retain proposal coverage. All other active scoring channels require per-channel, per-horizon forecast qualification. An endpoint raw-channel head alone does not qualify three seconds of evolved agency, control or contact history.

The terminal value begins after the last simulated interval. Do not count those first three seconds again in the terminal value. Use the same normalization, duration and intention in every alternative. An invalid mandatory channel disqualifies that forecast; it is not silently assigned zero. Harm/support constraints apply before ranking. Remove the old requirement that learning progress must be positive to select a healthy movement. A familiar movement can win on retained usefulness when its learning-progress term is zero.

Define object control without a grasp bonus. Measure control separately in similar starting conditions. Cluster normalized starting joint pose, object-to-palm geometry, body support and digit contact into 16 contexts using k-means on preserved observations. Freeze those cluster centres and scales for this producer version. In each context, bounded exploration randomly assigns small signed control changes from the physically permitted envelope. Save the assigned change, the filtered command, actual duration and object identity. Correct object motion for the camera/body motion in A before fitting an effect.

Within each context fit object_change = A*starting_features + B*assigned_control_change by ridge regression, with penalty 0.01 after normalization. This is a local effect estimate, not one global matrix for every pose. Include all assigned trials, including guard interventions; discarding only failed commands would bias the result. The assignment estimates the effect of the complete guarded control path. Fit a separate context when filter saturation or guard conditions differ; never reinterpret the assignment as an unfiltered executed command. Require at least 20 trials per tested control coordinate, full rank in the randomized assignment matrix, and a held-out error improvement over the start-state-only model exceeding the held-out measurement-noise bound. These support thresholds and penalty are proposed settings. Unsupported contexts have no control estimate.

For a supported context use log det(I + R^-1/2 * B * C * transpose(B) * R^-1/2). Here R is object-motion measurement-noise covariance from repeated observations, with a frozen positive eigenvalue floor; C is the covariance of permitted randomized command assignments, fixed for that context/version. This measures distinguishable object motions caused by those allowed changes. It can credit pushing, holding or manipulation. It does not contain a ball detector or a named reach routine. A regression improvement alone is insufficient if object identity or camera-motion correction is unreliable.

Use this measured capacity as the proposed object component of the controllability channel. Train a two-layer, 256-unit GELU capacity head from the starting state/contact relationship to the supported context's measured capacity, using squared error and its sampling uncertainty. Check it on held-out starting states. The native channel forecast consumes that head's output at each predicted state only within a qualified context. This allows a retained contact arrangement to have value without rewarding continuous shaking. Invalidate the estimate when identity, context, producer version or contact validity changes beyond calibration. Raw pressure or image motion supplies no capacity label. This producer changes the channel's meaning and requires a versioned matched comparison before adoption.

For each real window, teach a new state-and-intention value head with:

G_c(h) = sum over observed intervals ending by h:
           gamma(elapsed) * measured_dt * N_c(actual_channel_c)
         + gamma(d) * V_target_c(last_state,g,h-d)  [eligible cuts only]
V_c(S,g,0) = 0
value_loss = mean over valid channels of (V_c(start_state,g,h) - G_c(h))^2
G_phi(h) = sum_observed gamma(elapsed) * [gamma(measured_dt)*phi(next,g)-phi(current,g)]
           + gamma(d) * V_target_phi(last_state,g,h-d)  [eligible cuts only]
potential_loss = (V_phi(start_state,g,h) - G_phi(h))^2

Use h in 50 ms increments up to three seconds, including 0.5, 1, 2 and 3 seconds. Record targets from the actual timestamped readings for each requested duration; do not interpolate an unobserved return. A complete target is an actual contiguous window of exactly that duration under the same retained intention and behavior policy; it has no added tail. During warm-up use only those complete windows. Later, a cut after d seconds may use a fixed target-head estimate for h-d only if that remaining duration, channel and policy already have a held-out error bound. Otherwise save the partial record without making that value target. Never treat a three-second window ending as the end of all future usefulness, or bootstrap an unspecified infinite return.

The head concatenates core state, normalized body/object/contact fields, validity masks, intention descriptor and remaining duration h. Two 256-unit GELU layers output one value per active channel and a separate accumulated goal-potential output. Its target copy updates only after an accepted finite optimizer update: target = 0.995*target + 0.005*current. Stop gradients through that target while calculating the loss. The three-second continuation used by the planner is taught from actual three-second windows beginning in the relevant states; it never counts the explicit preceding three seconds again.

Only windows in which that same intention g was actually retained and the specified behavior policy ran can teach this goal-conditioned value. Successful completion keeps that relationship active for the rest of its evaluation period, so early success still supplies later maintenance windows. Both successes and failures enter the dataset. Exploration without a pursued g supplies forward lessons and retrieval examples, not invented goal-conditioned targets. Freeze the acting chooser, forward predictors, encoder, value heads, raw-channel normalization and weights for one collection epoch. Train candidate copies offline from collected data; promote a candidate only between epochs after qualification. This prevents each optimizer update from changing the behavior being measured. Pin those versions in every record. A changed chooser starts a new value epoch. Preserve unfinished old-epoch windows under their old version; complete them only from matching old-version evidence, otherwise retain them as partial evidence without a new-epoch value lesson. Re-encode raw windows after an encoder change, or retain their old representation; never mix incompatible features.

While continuation is unqualified, use zero continuation and the qualified three-second forecast plus explicit goal-distance heuristic. Label that shorter comparison in the decision record. It can collect actual intention-bearing windows inside the qualified physical envelope. Goal acquisition from exploration is allowed only when the short-horizon raw utility forecasts qualify; otherwise exploration continues. No earlier exploratory endpoint is relabelled as the intention that supposedly caused it.

The value target counts actual utility throughout the six-second intention period, including failure and protective recovery. At its scheduled end the finite horizon is exhausted. Harm requiring protection or loss of identity stops object-directed commands but does not erase later costs: retain g with a failure flag, run the frozen protective policy, and collect its actual channels to the period end. These failed-branch windows are valid targets for the defined policy. Potential increments are zero during the failure branch rather than a jump to the satisfied-goal potential. Include failed periods in the dataset. If the physical world ends before those readings exist, retain the last harm reading and a censored-window flag; do not fabricate the remaining return or teach a complete h target. Such incomplete attempts still count as physical failures in the ability/adoption comparison. Normal achievement keeps the relationship-maintenance chooser active and supplies actual maintenance windows. A pause preserves the pending window, intention and elapsed simulated time. A time-limit cut follows the remaining-duration rule above and never crosses a reset. A physical fault that ends the world records actual harm and censors the unfinished duration target, as above; it is never removed from the physical failure count. A logging or process failure with missing observations is different: retain it as incomplete evidence, do not fill the missing interval with zeros, and report its count separately from physical failures. If a support shift is followed by measured control benefit within the observed window, that benefit enters the earlier state's G target. This is how a later result changes an earlier value estimate. Adoption also compares physical termination rate, identity-loss rate and observed harm against the same-state reference; reject a producer/chooser that increases any of these beyond the declared matched uncertainty, even if its average value score improves. Censored runs are reported separately and cannot improve success rates by disappearing. Benefits beyond the declared six-second comparison remain outside this initial chooser until a longer horizon is qualified.

G · Act briefly, read the result and change the next command

Input: the chosen first row and the actual control-filter state. Calculation: send that row through the production body, gaze and finger paths for one 50 ms interval. Read the new joint angles, images and touch. Output: one real before/command/after record and a new starting state for the next choice. The intention stays; the remaining movements may change.

If the index finger contacts first, its new pressure is part of the next state. Alternatives that keep closing that finger predict more pressure. Alternatives that stop its closing while adjusting the thumb predict a different result. The same score chooses between them. There is no rule that all fingers must curl together, or that contact must wait for the end of a 500 ms picture column.

Acquisition, uncertainty, interruption and learning ownership

Untrained forecasts cannot certify their own safety. The acquisition route is the existing physical exploration producer restricted to its recorded joint/strength/speed bounds, with actual harm/contact limits enforced by the production guard. Random variations remain inside that envelope and are logged as randomized exploration. If no such envelope is qualified for a body/scene, the next implementation gate is a bounded copied-state physical comparison of that envelope; no exploratory launch is authorized by this document. Do not demand a learned grasp before permitting any experience that could teach grasping.

Qualification compares saved pre-action forecasts with later observations on held-out windows, separately by channel, body/contact context and 50 ms through 3 s horizon. For an initial choice rule, use the empirical 95th-percentile absolute error only after 100 valid held-out windows in the relevant stratum; otherwise label the estimate unavailable. These sample/error choices are proposed engineering settings. Rank a predicted advantage as resolved only when it exceeds twice the appropriate error bound. Passing a one-row forecast does not qualify a three-second contact sequence. A changed model version rechecks held-out errors; acquisition within the physical envelope remains available while a new forecast is unqualified.

An actual protective interruption closes the record at its measured elapsed duration and records every sent substep. The intention record and g remain for attribution; harm or identity loss switches execution to the failed protective branch. A partial interval is learned only by a duration-aware path qualified for that duration; otherwise retain it as physical evidence and omit the incompatible one-row lesson. Never teach a full 50 ms forecast from a shorter interval.

Forward prediction parameters receive matched actual next-state losses. State-and-intention value parameters receive G targets from actual windows. Perception correspondence/calibration receives stereo and temporal reprojection errors, never future simulator coordinates as acting inputs. Retrieval adds the actual sequence to memory; it is not a gradient update to an unnamed proposal model. Existing canonical lessons keep their original meanings; native request-conditioned lessons have their own schema. Preserve all existing weights, optimizer state, experience, pending windows, intention, world states and random-generator state in a consistent checkpoint.

H · Decide whether the full loop works

The object begins beyond arm-only reach. The body must change its position, the hand must reach around the surface, and opposing fingers must retain the object when it is lifted off the stand. Run the same task from saved starting states before and after learning. Record the chosen commands, predicted motion and measured motion together. Count failed attempts as attempts.
