VERDICT AND CORRECTION OF MY EARLIER ACCEPTANCE
Reject the claim that this is a complete mechanistic solution. My earlier review accepted topic coverage as if it supplied the mechanism. That was wrong: naming state, proposals, value, learning and preservation does not specify the computations connecting them. The sentences 'Use learned outcome proposals' and 'vary commands and their timing together' conceal missing producers. The score 'predicted effects ... + later value' conceals missing quantities and update rules. My earlier 'no additional material conceptual omission' acceptance is withdrawn. The supported clearance measurements remain useful, but they prove separation, not wrapping or opposing contact. The current review paragraph must not continue to advertise unqualified acceptance.

The guide's Rule 11 is the central failed requirement: actual input, computation, output and next consumer. For learning, add the actual target and the parameters changed; for a decision, add the refusal/failure branch. Calling an unchosen algorithm an 'implementation setting' does not answer it. The basic mechanism belongs beside the component's first introduction, not only inside an engineering expander.

ACTIONABLE FINDINGS

S01 — 'Keep track of the body and the object' hides the state representation.
Locations: parts 1/2/5; section 5A; engineering step 1. The document never identifies what numbers represent object position, motion, identity, support or touch, or how their validity survives occlusion. Exact simulator coordinates are excluded as an acting shortcut, but no replacement estimator is specified.
Source: NativeInputV1 (native_contract.py:90) already specifies sensory tokens, transformer context, memory bias, achieved body pose, mean eye angles, preceding controls, masks, time and configuration. native_rollout:678 carries predicted tokens/context/pose/eye angles; it explicitly holds skin positions/features, spatial state and other inputs at its end. This is not an object/support estimator supplied by the word 'memory'.
Required rewrite: give the existing state fields and sources, then name each additional representation selected for object/support/contact reasoning, its observed training target or self-supervised observation loss, and its consumer. Explain how missing/occluded observations preserve an estimate and increase uncertainty. If the design uses latent sensory tokens rather than explicit coordinates, say how the intention, achievement check and value read those same tokens without assuming a hidden object tracker. Failure: two relevant situations map to the same actionable state, or an unobserved coordinate is silently treated as measured.

S02 — 'Propose possible outcomes' does not create a goal.
Locations: part 3, section 5B, engineering step 2. Neither a proposal algorithm nor the representation of an outcome exists in the explanation. 'Hold and move the ball' is a human task description, not an input the present model can generate or compare.
Source: LemLite.goal_ring (lem_model.py:994, 4874-4910) stores and ranks remembered moments; SelfValueReader adds a presence-correlation bonus to those moments (self_value_reader.py introductory contract and raw_value:213). OutcomeIntention (outcome_value.py:560) stores named observed feature intervals/context/suffix, is explicitly unconnected to choice, and declares achievement on one lived step. It does not generate object outcomes or prove retained grasp.
Required rewrite: specify where candidate outcome vectors come from, how they are matched to the current sensed context, and how one is selected. A concrete reuse option is retrieval of previously OBSERVED endpoints and associated action windows, with current-state reforecasting; a new learned generator requires an explicit training pair and loss. Select and explain one option. Store desired observed features separately from the plan. Specify duration-based achievement, invalidation and same-current-state replacement comparison. Failure: the ball moves or disappears, the intended object changes identity, the short goal ring overwrites the episode, or a momentary touch closes a hold intention.

S03 — 'Useful effects' does not define why grasping should win.
Locations: part 6, 5B/5E, engineering step 4. The page substitutes 'gaining control' and 'useful learning' for an actual measured value. An object being present is not an action consequence. Saying that a mastered action remains useful does not supply a nonzero value for it.
Source: _wellness_channel_vector (lem_model.py:10085) produces named channels; wellness_channels.py:93-105 defines channel order and weights, with efficiency weight ZERO by default. rank_values:502 normalizes and combines those channels. SelfValueReader explicitly states its presence link is predictive, not causal and not a reward. shadow_rule (sequence_shadow.py:109-143) rejects healthy choices to existing exploration when all eligible L <= 0.
Required rewrite: name the active channel set, units/signs, validity, normalization and the exact comparison order. Separate bodily harm, durable usefulness and learning progress. Remove the mandatory positive-L gate in the PROPOSED rule and state what actually ranks a familiar useful action. If object-control value is added, define the measured, action-conditioned quantity and why it belongs under existing project goals; do not smuggle in a 'ball grasped' bonus. Explicitly address the case where every available channel values holding still equally or more: the current goal definitions do not guarantee that grasping is selected. Failure: arbitrary task reward, presence confounding, reward for surprise/noise, or familiar success discarded at L=0.

S04 — 'Timed combinations' does not define a sequence the execution path can receive.
Locations: planner card, 5C, shared-record table. Body commands, finger joint requests and gaze requests are separate interfaces. Duration is not an interchangeable scalar on every existing predictor.
Source: NativeInputV1:90 has sent [B,H,9] in dispatch units, requested_gaze [B,2] in radians, joint_goal [B,J] in radians, mask_state/handle_mask, preceding commands and order age. native_rollout:678 accepts one entry per MODEL STEP; held commands repeat in the list. _causal_execution_candidates (lem_model.py:9125) routes explicit finger targets through the same smoothing/projection as other alternatives.
Required rewrite: show one candidate as a timeline of these fields, define how start times become indices on the existing model-step clock, and how run lengths express duration. Show simultaneous gaze/body/finger entries in the same row. Predict each repeated step rather than asserting that a one-step model predicts an arbitrary long command in one call. Name the authority/priority if ordinary control, finger control and gaze control request overlapping fields. Failure: ignored columns improve a forecast, mismatched units, repeated filtering, or one channel's command silently replaces another's.

S05 — 'Change selected joint requests' leaves the search algorithm unspecified.
Locations: 5C and engineering step 2. Which requests, how much, how often, and why the changes improve after experience are unanswered.
Source: SequenceShadow._sequences:1733 copies planner, controller and hold continuations; it does not do this search. SelfIntention.choose:96 constructs six candidates and random position/quaternion variations, but does not search all joint/gaze/timing fields or train an outcome-conditioned sequence generator.
Required rewrite: choose a specific proposal/search procedure. For example, a proposed bounded sample-and-refit search must state its seed sources, adjustable executed fields, temporal blocks, sampling distribution, limit projection, candidate scoring, retained set, refit rule, stop budget and selected output. These are algorithm choices, not achieved performance. State whether proposals are only retrieval plus search or a learned network; for a network name conditioning inputs, action-window target and update loss. Do not say 'learned proposals' when no producer is identified. Failure: every candidate repeats the same command, changes nonexecuted fields, or the search never generates support-before-reach combinations.

S06 — 'Predict contact over time' omits the contact transition and its lessons.
Locations: 5D, contact table and status row. Body pose alone cannot supply pressure, slip or object movement. The page never identifies the predicted sequence of contact quantities, their temporal resolution, or which later step consumes it.
Source: ContactConsequences.forward (lem/model/contact_consequences.py:46) takes skin-site positions/features, context/spatial state, actions and durations and returns endpoint skin features/capacity. Its loss:79 uses observed log-feature differences. LemLite:762 explicitly refuses experimental mechanical contact learning without pressure-history prediction. native_rollout holds the skin/spatial inputs.
Required rewrite: identify the per-step observed contact features, actual start/end alignment and recurrent update for them; give the loss against observed pressure/shear/slip history and object/support observations. State how predictions update the next branch state and the score, and how a new actual contact reading changes the next control. Do not substitute FK/IK for this transition. Failure: the contact head outputs a summary once while future decisions keep original touch, or object motion is inferred merely from fingertip closeness.

S07 — 'Later value' is neither a complete score nor a defined delayed lesson.
Locations: 5E/5G and engineering steps 4/6. The compact formula does not state sign, units, discounting, double counting, tail boundary or policy meaning. 'Use later observed results' does not show how an early estimate changes.
Source: ValueHeads/features_of (outcome_value.py:101/147) read 25 numbers: five current channels, five validity flags and fifteen averages. No object state/intention enters. OutcomeWindow._target:306 forms a time-weighted sum of subsequent observed channels and an optional last-state continuation. TAU_S=20 is a declared assumption. These heads are diagnostic only. The raw five-channel list differs from the full wellness ranking.
Required rewrite: write the chosen target and score explicitly, with each term defined. A coherent proposed form is the sum of discounted per-interval observed channel integrals plus discounted last-state value, with the same starting state, elapsed-time convention and intention for every comparison. State which channel weights and frozen normalization produce a scalar; keep learning-progress credit separate if otherwise double counted. Give the value loss, stop-gradient bootstrap, update recipient, target policy and treatment of changed encoders/normalizers. True termination ends the tail; pause/time-limit truncation preserves the valid continuation. Demonstrate symbolically how later observed benefit changes the earlier prediction; do not invent forecast numbers. Failure: shorter intervals manufacture more reward, current comfort aliases distant/near objects, or an interrupted attempt loses its delayed credit.

S08 — 'Check uncertainty' and 'bounded exploration' hide the acquisition path.
Locations: 5D/5G and engineering step 5. No rule tells the system what to do while new predictors are untrained, so the plan can collapse into indefinite fallback.
Source: native predictions start unqualified; outcome_value.abs_error is explicitly training error, not calibration. SelfIntention ties acting permission to exact model/perception fingerprints; changed weights invalidate it. Shadow comparison never acts.
Required rewrite: distinguish physically limited exploratory actions from decisions justified by a forecast. Name the existing exploration producer, perturbation domain, intervention limits, collected lesson, and rule that moves a learned prediction into acting use. Calibration must compare fixed prior forecasts with later actual observations, with channel/horizon/context/model binding; comparing an updated forecast to its own training target is not independent evidence. Define what happens when only some channels are reliable. Failure: unknown risk treated as zero, every update removes all usable action authority, or qualification requires an ability that cannot be explored first.

FOLLOW-UP DESIGN DIRECTION RECEIVED DURING THIS BOUND
Bootstrap retrieval of observed future outcomes and actual action windows is more specific than an unnamed learned proposal network. However, the present goal ring's whole sensory tokens do not identify an object across views or measure its control. The narrow reusable representation is a reference to a raw sensed observation WINDOW, with masks, timestamps and both start/goal re-encoded under current encoder weights. That defines a sensory-return outcome; it must not be labelled 'this ball held' without a specified perceptual association and action/contact-conditioned object-motion representation. The full object-specific design still needs that mechanism. Merely concatenating latent vectors and calling them descriptors does not provide it.
Retrieval also needs a learning-policy qualification: relabelling every experienced future endpoint as the goal does not turn all those actions into attempts made to pursue that goal. A proposed goal-conditioned value must state which policy its targets predict, how actual failed attempts remain represented, and how hindsight-selected endpoints avoid success-selection bias. The existing policy_id binding records a behavior identity; it is not an off-policy correction algorithm. These points must be resolved in the new document's representation and delayed-value sections.
